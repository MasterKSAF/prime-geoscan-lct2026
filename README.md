# Планер / PRIME — Геоскан, ЛЦТ 2026

Задача №5: **«Сервис планирования и распределения беспилотных авиационных работ»**.

Планер принимает участки и работы, подбирает совместимые БВС, рассчитывает маршруты и расписание, сравнивает время завершения с суммарным налётом. Оператор проверяет вариант, запускает модельную симуляцию и выгружает отчёт выбранного запуска. Интерфейс: **Миссии / Редактор / Выполнение / Парк БВС**.

Участники: **Калеев Сергей, Миняев Револь**. «Планер / PRIME» — название продукта, а не неподтверждённое зарегистрированное название команды.

## Запуск в Docker

Нужны Docker Desktop с Linux containers и Git. Первая сборка требует интернета. GPU и учётные записи погодных сервисов не нужны.

```powershell
git clone https://github.com/MasterKSAF/prime-geoscan-lct2026.git
cd prime-geoscan-lct2026
docker compose -f compose.planner.yaml up -d --build
docker compose -f compose.planner.yaml ps
```

Открыть **http://127.0.0.1:3016/planner**. Дождаться статуса контейнера `healthy`. API: `http://127.0.0.1:3016/api/planner/health`. Ожидаются `status: ok`, `missionEngineVersion: 0.3.0`, `flightReady: false`.

Порт 3016 привязан только к localhost. Не открывать этот инженерный стенд в интернет без отдельной защиты. Если порт занят другим стендом, сначала согласовать его остановку. Compose ограничивает runtime двумя CPU и 1 ГиБ памяти; сборке требуется больше ресурсов.

```powershell
docker compose -f compose.planner.yaml logs --tail 100
docker compose -f compose.planner.yaml stop
```

`stop` не удаляет пользовательскую библиотеку. Данные миссий хранятся в браузере, а не внутри контейнера.

## Запуск разработки без Docker

Node.js 24 LTS, npm из комплекта Node. Проверенный Docker закреплён на Node 24.14.1 по digest.

```powershell
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3015
```

Открыть http://127.0.0.1:3015/planner. Порты 3015 и 3016 имеют **раздельные** хранилища браузера. Для переноса использовать JSON/YAML, а не ожидать автоматического появления миссий на другом порту.

## Проверка

```powershell
npm run typecheck
npm run test:planner
node --experimental-transform-types --test tests/acceptance/track5-readiness.test.ts
node --experimental-transform-types scripts/verify-missions.ts http://127.0.0.1:3016 output/expert-api
node --experimental-transform-types scripts/verify-mission-run-report.ts docs/planner/submission/evidence/browser/run.report.json
node scripts/verify-submission.mjs
```

Приёмочный тест A8 требует работающего стенда 3016. Модульная команда не включает вложенные приёмочные тесты. Не проверять на реальном БВС. Полные команды браузерного и сравнительного прогонов: [чек-лист](docs/planner/submission/REVIEW-CHECKLIST.md).

Текущие сохранённые результаты: 509 модульных, 8 приёмочных, 20 браузерных, 11 базовых HTTP-проверок и 6 проверок расширенного API. При первом HTTP-прогоне воспроизвёлся известный сбой 503 после отклонения большого запроса; повторный прогон прошёл. Даты, логи и границы указаны в [отчёте](docs/planner/submission/VERIFICATION.md). Число тестов не является баллом жюри.

## Первый показ

1. «Миссии» → «Готовые примеры» → «Демо 1»: фотосъёмка квадрата.
2. «Редактор» → «Расчёт вариантов» → рассчитать → проверить и подтвердить.
3. «Выполнение» → «Выполнить миссию». Ускорение симуляции подписано явно.
4. Из строки миссии открыть отчёт и выгрузить результат.
5. Демо 2 показывает препятствия и разведение; демо 3 — недостаточный заряд и проверку исправления.

[Подробный сценарий на 8–10 минут](docs/planner/submission/DEMO-SCRIPT.md). Демо 2 использует исходный KML экспертов с 3 201 препятствием. Работы, базы, ветер и рабочие профили в демонстрации модельные. Каталог реальных моделей и источники параметров находятся отдельно в «Парк БВС».

## Форматы

| Формат | Назначение |
|---|---|
| Миссия JSON/YAML 2.0 | Полный переносимый вход: работы, участки, сроки, парк, условия |
| GeoJSON/KML на входе | Координатная геометрия, не цифровая модель рельефа |
| prime-fleet JSON 1.0 | Профили БВС, текущая батарея и базы |
| prime-restrictions JSON 1.0 | Высотные и временные ограничения |
| KML/GeoJSON результата | Плановые маршруты, не команды проверенного автопилота |
| Evidence JSON | Вход, кандидат, проверки и хеши расчёта |
| prime-run-report JSON/HTML | Снимок конкретного запуска, журнал, состояние и цепочка пересмотров |
| KML препятствий | Полный оригинал, каталог, полигоны/линии и защитные отступы. Без DEM используется горизонтальный обход |
| ZIP / BagIt 1.0 | Самодостаточные доказательства миссии с исходным KML, маршрутами, журналом и SHA-256 |

Схема: [mission-v2.schema.json](docs/planner/contracts/mission-v2.schema.json). API: [описание](docs/planner/api-v2.md). Примеры: [public/planner/scenarios](public/planner/scenarios).

## Границы и происхождение данных

Расчётная модель не подтверждает разрешение или безопасность реального полёта. Поддержаны Gemini, 801 и **явная упрощённая самолётная модель 201**. Паспортные максимумы и модельные рабочие бюджеты различаются.

Погода загружается как прогнозный снимок с происхождением; ядро использует выбранный вектор ветра, а не реальное 4D-поле. Реальных бортовых данных и DEM нет. Энергетическая модель линейная, без калибровки по полётным логам. Неизвестное качество реальных материалов не считается подтверждённым.

Параллельные миссии разрешены для раздельных районов с запасом и разных БВС. Пересмотр плана выполняется на безопасной наземной точке. Фонового автозапуска при закрытом браузере нет.

Очистка браузера удаляет библиотеку: экспортируйте резервные копии. Карта OpenStreetMap и сервис прогноза используют внешнюю сеть; район запроса виден провайдеру. Сохранённые миссии с ручными условиями считаются локально, подложку можно отключить.

## Структура

```text
app/planner/                         Веб-интерфейс
app/api/planner/                     Расчёт, анализ, погода, health
components/planner/                 Экраны и элементы интерфейса
lib/planner/                        Контракты, маршруты, поиск, проверки, журналы

scripts/                            Проверка и упаковка
docs/planner/submission/             Актуальный комплект эксперта
  presentation/                     PPTX, автономный просмотр, текст выступления
  assets/                           Скриншоты инструкции
  evidence/                         Тесты, API, запуски, benchmark
```

Исторические отчёты в других папках описывают собственные даты, а не текущую приёмку. Материалы других треков, записи встреч и установщики не нужны для запуска и не входят в новую поставку. Репозиторий закрытый. Доступ экспертам владелец предоставит отдельно, когда будут известны их логины.
