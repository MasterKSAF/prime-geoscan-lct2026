# Planner — планирование групповых полётов БВС

Веб-стенд для трека 5 «Геоскан», ЛЦТ 2026. Создаёт маршруты для нескольких БВС, сравнивает время завершения и общий налёт, проверяет ограничения, воспроизводит миссию и выгружает доказательства.

Рабочее ядро **0.4.0**, формат миссии **2.0**. Стенд моделирует полёты: физические БВС не подключены. Расчёты маршрутов и проверки выполняются программно; телеметрия, погода демо и результаты сенсоров — модельные данные.

## Запустить

Нужен работающий Docker Desktop в режиме Linux-контейнеров. **Из полного ZIP:** распакуйте архив, откройте терминал в каталоге `source/` и выполните (Git и доступ к GitHub не нужны):

```powershell
docker compose -f compose.planner.yaml up -d --build
docker compose -f compose.planner.yaml ps
```

**Из GitHub:** после предоставления доступа к актуальной версии, дополнительно нужен Git:

```powershell
git clone https://github.com/MasterKSAF/prime-geoscan-lct2026.git
cd prime-geoscan-lct2026
docker compose -f compose.planner.yaml up -d --build
docker compose -f compose.planner.yaml ps
```

Откройте [стенд](http://127.0.0.1:3016/planner). Репозиторий пока закрыт: для клонирования нужен предоставленный владельцем доступ.

Сборка устанавливает зависимости и FFmpeg, проверяет типы, запускает автоматические тесты и собирает приложение. Контейнер ограничен 2 CPU / 1 ГиБ; GPU не требуется. Первый запуск требует интернета для скачивания зависимостей. Карта использует внешнюю подложку.

Лимит 1 ГиБ относится к работающему сервису, не к сборке. Типы, тесты и production build проверены отдельно с 4 ГиБ памяти; точный минимальный объём для сборки не измерялся. Не запускайте компиляцию внутри уже работающего контейнера с лимитом 1 ГиБ.

```powershell
# Проверка работающего сервиса
Invoke-RestMethod http://127.0.0.1:3016/api/planner/health
# Логи при ошибке
docker compose -f compose.planner.yaml logs --tail 100 planner
# Остановка без удаления файлов проекта
docker compose -f compose.planner.yaml stop
```

В health проверяйте `status: ok` и `missionEngineVersion: 0.4.0`. Поле `engineVersion: 0.1.0` относится к старому API и не является версией текущего планировщика.

Правила высот и времени загруженных зон: [KML, AGL/AMSL/FL и модель пересчёта](docs/planner/expert-materials/2026-09-23/zone-rules.md). [Полный аудит исходных слоёв](docs/planner/airspace-source-audit-2026-09-24.json).

## Первая проверка — три миссии

1. На экране «Миссии» откройте **Демо 1** в редакторе → «Рассчитать варианты» → выберите план → «Проверить и подтвердить».
2. Во «Выполнении» нажмите «Выполнить миссию». Время на экране — время симуляции; ускорение можно менять.
3. В «Отчёте» откройте результат, «Все проверки», скачайте маршруты и «Доказательства ZIP».
4. Повторите для **Демо 2** с препятствиями. **Демо 3** специально проверяет отказ: запуск недопустимого плана должен быть заблокирован.

[Пошаговый показ и ожидаемые результаты](docs/planner/submission/DEMO-SCRIPT.md).

**Сохраните нужные файлы до обновления страницы.** Демонстрационная сессия начинает работу с трёх примеров без прежних запусков и истории. Загруженные миссии и изменения сохраняйте через JSON, результаты — через ZIP. «Настройки → Начать с нуля» также очищает сессию после подтверждения.

## Камеры и качество съёмки — 0.4.0

В каталоге 9 профилей; установленная камера задаётся на конкретном БВС: **Парк БВС → Доступность → комплектация → Камеры → параметры → Сохранить параметры камеры**. Требования GSD и перекрытий остаются у работы; оптика БВС определяет расчётную высоту, полосу, шаг кадров и проверку смаза.

Pollux — мультиспектральная камера с NIR, не тепловизор. Неизвестные размеры/растр 801 и Riebo, а также объектив ZV-E10 не подставляются по догадке. Интервал 1 с и выдержка 1/1000 с в демонстрационных комплектациях — **модельные допущения (`assumed`)**, не паспортный или испытанный режим.

В одной раскладке работа использует один оптический профиль; её делят между БВС с эквивалентной оптикой, а другие профили сравнивают как альтернативы. Глобальная оптимальность не доказана. После обновления до 0.4.0 миссию нужно пересчитать; старые архивы результатов не переписываются.

## Разработка без Docker

Рекомендуется Node.js 24, как в Dockerfile; минимальная версия проекта — 22.13. Команды из корня:

```powershell
npm ci
npm run dev:planner
```

Откройте [режим разработки](http://127.0.0.1:3015/planner). Для преобразования записи в MP4 без Docker нужен FFmpeg в PATH. Параметры API и форматов: [API v2](docs/planner/api-v2.md).

## Использованные нормативные материалы

При подготовке учитывались ПП РФ №138, ГОСТ Р 59328-2021, ГОСТ Р 70078-2022; ГОСТ Р 59562-2021 изучался как контекст. Также использованы ТЗ, ответы экспертов и документация Геоскана. [Что именно реализовано и откуда взяты ограничения](docs/planner/normative-basis.md).

Предел ниже 150 м принят по уточнению экспертов. Высота 100 м сама по себе не означает разрешение на полёт. Стенд не заменяет согласование воздушного пространства и не заявляет полное соответствие всем пунктам перечисленных документов.
