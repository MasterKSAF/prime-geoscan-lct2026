# Планирование беспилотных авиационных работ

ЛЦТ‑2026 · Бизнес-трек · Задача №5 · Постановщик: «Геоскан»

Веб-сервис для распределения съёмочных работ между беспилотными воздушными судами (БВС) с учётом характеристик аппаратов, камер и доступных точек взлёта.

**Задача**

Распределить съёмку между БВС, минимизируя **время выполнения либо суммарный износ**.

**Входные данные**

Характеристики БВС и камер; точки взлёта; область и виды съёмки.

**Результат**

Веб-сервис расчёта оптимального полётного задания.

Краткое описание по сохранённой карточке задачи. Полное ТЗ и критерии оценки не получены; предложенные ниже функции — рекомендации, а не требования организатора. [\[1\]](#s01)

**Рекомендация:** оптимизатор загрузки разнородного флота с двумя целями, проверкой ограничений и сравнением планов. Сначала математическое ядро; ML — при наличии данных и измеримого улучшения прогноза времени или расхода ресурсов.

Характеристики заявлены производителем для указанных модификаций. Производительность зависит от камеры, перекрытий, формы участка и условий. При расчётах данные полного ТЗ имеют приоритет.

**Модель данных:** конкретный борт + установленная нагрузка + доступный ресурс + стартовая площадка + готовность. Несколько видов съёмки можно объединять в один вылет только при подтверждённой совместимости.

### Что проверить в Planner

Руководство 2.8 от 22.09.2025: GSD и перекрытия — стр. 41–42; задания по KML — 60; сетка для бригад — 61–62; GCZ — 63; несколько БВС — 96; «Небосвод» — 119. GCZ — ZIP с проектом и журналами, но это не открытая спецификация генерации совместимого файла. [\[8\]](#s08)

**Первый вариант обмена:** KML с распределёнными участками + ведомость назначений, затем проверка в Planner. Это гипотеза интеграции, не готовая загрузка полётных команд: параметры камеры, высоты и перекрытий должны совпадать. API Planner и промышленного автопилота не подтверждены.

**Порядок изучения:** Planner → Trainer → логи и ресурс → остальное ПО.

<a id="math"></a>

### Модель времени и износа

**Единица работы:** участок × вид съёмки. Сначала рассчитываются допустимые варианты для конфигураций «борт + нагрузка», затем — назначения. Дробление полигонов допускается только по ТЗ; регулярная сетка — базовая дискретизация, не гарантированный оптимум.

Время завершения = max(время окончания работ по используемым бортам). Вылет = подготовка + старт + перелёт + съёмка + возврат + посадка. Между вылетами: смена нагрузки / АКБ, зарядка, обслуживание, ожидание. Параллельные операции не складываются в одну очередь автоматически.

**Износ:** сначала использовать формулу организатора. Если её нет — согласовать условный показатель из часов, вылетов и циклов АКБ с явными коэффициентами. Прогноз реальной деградации требует истории эксплуатации и обслуживания.

Условный ресурс W = Σ(a × часы + b × вылеты + c × циклы АКБ + …) Это пример структуры, не физический закон и не формула «Геоскана».

**Не смешивать:** гарантия ≠ полный ресурс; расстояние ≠ износ; сумма времени в воздухе ≠ срок завершения. Для двух целей показывать альтернативы и компромисс; веса и предельный срок задавать явно.

| Ограничения | Что проверять |
| --- | --- |
| Качество | Вид съёмки, камера, разрешение, перекрытия, ракурс и полное покрытие. |
| Доступность | Конкретный борт, нагрузка, стартовая площадка и возможность возврата. |
| Ресурс | Доступная длительность, резерв, батарея / топливо и межполётные операции. |
| Геометрия | Границы и отверстия полигонов, запретные зоны, рельеф, повороты и набор высоты. |
| Совместная работа | Операторы, площадки, одновременность, пространственно-временные конфликты. |

Отсутствующие параметры фиксируются как допущения. Статическое назначение не доказывает безопасность совместного полёта.

### Алгоритм и место ML

**Старт:** генератор вариантов → жадное назначение → локальные улучшения или дискретный решатель. CP‑SAT — кандидат для назначения и расписаний; непрерывную геометрию считать отдельно, величины корректно переводить в целые. [\[51\]](#s51)

**Статусы:** FEASIBLE — допустимо, без доказательства оптимальности; OPTIMAL — оптимально в принятой модели; UNKNOWN — не доказана ни выполнимость, ни невозможность. Для эвристики: «лучший найденный план за указанное время». [\[51\]](#s51)

**ML:** добавлять для измеряемой ошибки расчётной модели, например прогноза времени по логам. Проверку отделять от обучения по полётам, площадкам или времени; оценивать против простой модели.

<a id="demo"></a>

### Проверка и защита

| Базовый алгоритм | Что сравниваем |
| --- | --- |
| Равномерное распределение | Выигрыш против простого деления допустимых участков. |
| Ближайший подходящий борт / старт | Выигрыш глобального назначения против сокращения перелётов. |
| Жадное назначение по завершению | Вклад последующих перестановок и решателя. |
| Точный эталон на малом сценарии | Близость эвристики к доказанному оптимуму модели. |

**Метрики:** выполненные работы и нарушения → срок завершения → полётное время, вылеты и холостые перелёты → согласованный ресурс → время расчёта и разрыв до нижней оценки, если доступен. У сравниваемых методов должны совпадать данные и ограничения.

**Тесты:** один борт; симметричные аппараты; несовместимая камера; несколько вылетов; удалённый старт; невыполнимое задание; потеря борта; мелкие и узкие участки с отверстиями; ухудшение доступного времени полёта.

**Демонстрация:** входные данные → базовый план → минимум времени → минимум ресурса → изменение ограничения → пересчёт → протокол и выгрузка. Уровни проверки различать: собственный валидатор, Trainer, реальная эксплуатация.

Замеры выигрыша и интеграция в рамках исследования не выполнялись. Проценты улучшения допустимы только после тестов с указанным базовым алгоритмом.
