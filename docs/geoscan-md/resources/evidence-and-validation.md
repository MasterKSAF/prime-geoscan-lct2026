# Как доказать выполнение, а не только показать анимацию

Это план будущих проверок. Исследование документации не создало результатов полётных испытаний или benchmark. Основание: [ТЗ](../geoscan-track5-tz.md), [логи MP](mission-planner-review.md), [протоколы](protocols-and-interoperability.md), [Planner](geoscan-planner-review.md).

## Минимальная матрица

Дополнение по реальной экосистеме Геоскана: [проверки GS01–GS11 и состав логов](geoscan-site/implementation-addendum.md). Оно уточняет EV02/EV03/EV06/EV09/EV12, но не объявляет ни один тест пройденным.

| ID | Что проверяем | Сценарий | Обязательное доказательство |
| --- | --- | --- | --- |
| EV01 | Входные сущности из ТЗ | Старты/посадки, парк, зона, тип работ, ограничения, резервы | Исходный JSON, схема, отчёт валидации |
| EV02 | Индивидуальное задание каждому выбранному БВС | Смешанный парк с несовместимыми нагрузками | Назначения, причины исключения БВС, профили с источниками |
| EV03 | Высота, скорость, точки и фазы | Набор, съёмка, развороты, возврат, посадка | Нормализованный план и отчёт обязательных полей |
| EV04 | Полное покрытие | Выпуклая зона, невыпуклая зона, отверстие, узкий участок | Независимо рассчитанное покрытие/непокрытие и допуски качества |
| EV05 | Воздушные ограничения | Запрет внутри зоны и на кратчайшем пути возврата | Проверка рабочих проходов, переходов, разворотов и посадочных процедур |
| EV06 | Энергия и ветер | Встречный/боковой ветер, малый остаток, недостижимая посадка | Баланс по фазам, резерв, расчёт выполнимости и корректный отказ |
| EV07 | Два критерия | Один набор входов, два режима | Значения обеих метрик для каждого варианта, единицы и определение завершения |
| EV08 | Эффективность/масштабируемость | Фиксированная серия размеров задачи | Baseline, время расчёта, CPU/RAM, результаты всех прогонов, не только лучшего |
| EV09 | KML/GeoJSON | Выгрузка и обратное чтение обеих версий | Файлы, schema-check, semantic diff, явная система высоты |
| EV10 | Современный браузер и демо | Чистый запуск и сценарий без сети после подготовки | Версии, startup log, инструкция, сценарий действий, скринкаст |
| EV11 | Сопроводительная документация | Проверка комплекта сдачи | Архитектура, алгоритм, запуск, пользовательское руководство, API при наличии, ограничения |
| EV12 | Дополнительный импорт/SITL | Выбранный GCS/firmware, в том числе сбой загрузки | ACK, read-back, TLOG и бортовой лог, версии, фактический результат выполнения |

EV12 — дополнительное доказательство, если делаем интеграцию; оно не подменяет обязательные EV01–EV11. Точные допуски покрытия/энергии и правила сравнения согласовать с экспертами.

## Структура одного пакета запуска

```text
evidence/<run_id>/
  manifest.json             # версии, время, seed, хеши, тип испытания
  input.json               # вход без неявных зависимостей
  profiles.json            # БВС/АКБ/сенсоры, источники, допущения
  environment.json         # ветер, DEM/CRS, система высоты
  plan.json                # канонический результат
  exports/                 # KML + GeoJSON; доп. форматы отдельно
  solver.jsonl             # ход расчёта, лимиты, статус остановки
  validation.json          # независимые проверки и причины отказов
  metrics.json             # обе целевые метрики, качество, затраты
  comparison.json          # baseline и вариант на тех же входах
  interoperability/        # импорт/ACK/read-back только если проверяли
  telemetry/               # настоящие логи стенда; не выдуманные данные
  report.md                # понятный вывод с ограничениями
```

План/входные данные неизменяемы внутри `run_id`; новый расчёт — новая версия. SHA-256 фиксирует целостность, но не делает недостоверный расчёт достоверным. Секреты, signing keys и персональные/закрытые координаты в публичный пакет не включать.

## Проверки, которые легко забыть

- Неполная загрузка миссии, повтор сообщений, отказ неподдерживаемой команды.
- Смена Home после повторного старта и несовпадение Home/EKF origin.
- Включение камеры после паузы; количество событий съёмки и файлов.
- Изменение маршрута без обновления UI, метрик или экспорта.
- Отсутствующий DEM, пустой или самопересекающийся полигон, точка на границе, неверная размерность единиц.
- Переключение активного БВС: команда/файл не должны попасть другому аппарату.
- Заданный seed не гарантирует побитовую воспроизводимость многопоточного решателя. Хранить число потоков, допуск и конфигурацию; для контрольных прогонов при необходимости использовать детерминированный режим.
- Заявление об оптимальности требует доказанного статуса решателя или границы/разрыва; хорошая эвристика не равна глобальному оптимуму.

## Чего недостаточно

Скриншота зелёной зоны, видео 3D, одного удачного примера, одного TLOG при потере связи или таблицы «100%» без открытых критериев. Проверки ограничивают риск в объявленных условиях; не гарантируют победу или безопасность реального полёта при любых условиях.
