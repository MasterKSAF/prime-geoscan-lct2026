# Gemini: ограничения, которых нет в коротком буклете

[Полное руководство, 76 страниц](../../../tmp/geoscan-resources/raw/gemini-full-manual.pdf). Номера ниже — физические страницы. Это инженерный разбор для программного планировщика, не эксплуатационная инструкция для полёта.

## Факты для профиля

| Источник | Подтверждённое условие | Значение для нашей реализации — инженерный вывод |
| --- | --- | --- |
| С. 10, 36 | Без дождя/снега; −15…+40 °C; ветер не выше 10 м/с; стартовая площадка минимум 5×5 м | Проверять допустимость сценария до оптимизации. Точка на карте ещё не означает пригодную площадку |
| С. 29–33 | На холоде возможна потеря до 30% ёмкости; двухслотовое ЗУ заряжает последовательно; примерно 75/105 минут до 95/100% при +25 °C | Отдельная очередь зарядки, а не два параллельных зарядника; температурный сценарий, а не постоянный коэффициент на все условия |

| С. 65–67 | PPK требует данных наземной GNSS-базы, параметров антенны и событий съёмки | GNSS-точность из рекламы нельзя выдавать за доказанную точность карты |

## Границы полноты короткой спецификации

Полное руководство различает PF1B, Sony UMC-R10C ранних комплектаций и Pollux. Для PF1B в таблице на с. 71 фокусное расстояние не заполнено, тогда как [буклет](../gemini-specs.md) указывает 20 мм. Хранить происхождение значения и уточнить фактический объектив; не смешивать камеры и их GNSS-смещения. Наклон камеры, переставляемый вручную, не моделировать как управляемый в полёте подвес. [С. 7, 19–28, 71 исходного руководства](../../../tmp/geoscan-resources/raw/gemini-full-manual.pdf#page=71).

## Что даёт прочтение остальных разделов

| Прочитанный блок | Практический вывод для проекта |
| --- | --- |
| Комплектность, обслуживание, хранение, перевозка, сборка | Проверка готовности должна иметь отдельные состояния «аппарат», «батарея», «нагрузка», «оператор». Наш сервис не заменяет техническое обслуживание |
| Камеры, накопители, управление съёмкой | Разделить тестовый кадр, команду экспозиции, подтверждённый кадр и файл. Предпросмотр сам по себе не подтверждает сохранение |
| Батареи и ЗУ | Моделировать не только заряд, но и доступность батареи после охлаждения/подготовки. Не объявлять время замены нулевым |
| Карты, рельеф, связь, предполётная подготовка | Офлайн-проверка должна выполняться с заранее подготовленными картами/DEM и конфигурацией. Наличие Wi-Fi/COM не доказывает открытый миссионный API |
| Автоматический, полуавтоматический, ручной режимы, неисправности | Смена режима и потеря GNSS — отдельные события. Не приписывать сервису автономную навигацию без GNSS на основании наличия ручного режима |
| Копирование, PPK, EXIF, файлы GNSS | Цепочка доказательств: задание → события → снимки → привязка → отчёт. Для трека планирования постобработка изображений — дополнение, не замена алгоритма маршрутизации |

## Как использовать в MVP

**Уточнение 17.09 после полной встречи:** рекомендация ниже об откладывании повторных вылетов устарела. Актуальный план включает простой повтор со сменной батареей/заданной готовностью; сложные очереди зарядников остаются расширением. См. [обновлённый план](../../planner/stage1-master-plan.md) и [мастер миссии](../../planner/mission-workflow-spec.md).

Основной вариант: одновылетный план с проверкой энергии и возврата. Расписание нескольких вылетов, батарей и последовательной зарядки — расширение после уточнения оценки у экспертов. Для него нужны реальные времена наземных операций, исходный заряд и число батарей/зарядников. Они не выводятся достоверно из максимального времени полёта.

RTKLIB, упомянутый в разделе PPK, — полезный следующий источник для геопривязки. В этом проходе его собственное руководство целиком не изучалось: это отдельная система постобработки, не часть заявленного корпуса планировщиков.
