# Геоскан Облако и качество исходной съёмки

Прочитаны полные тексты 14 указанных статей 15.09.2026. Ни регистрация, ни загрузка данных, ни изменение доступа не выполнялись. Это полезные ориентиры для интерфейса и контроля качества; само Облако не становится обязательной зависимостью решения.

## KB368 — базовый процесс Облака

Источник: [Краткое руководство](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/368/cat/181/kratkoe-rukovodstvo-po-rabote-v-geoskan-oblako).

Процесс разделяет проект, загрузку данных, проверку формата/CRS и создание веб-оптимизированного представления. Если CRS не распознана, загрузка приостанавливается; локальные координаты без позиционирования по умолчанию оказываются у нулевых координат. Для нас полезны понятные состояния импорта и запрет молчаливой подстановки координат.

Термин «публикация» здесь означает подготовку тайлсета для просмотра. Это не то же самое, что открытие анонимного публичного доступа, настраиваемого отдельно.

## KB387 — связка Metashape и Облака

Источник: [Загрузка проекта Metashape](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/387/cat/181/zagruzka-proekta-agisoft-metashape-v-geoskan-oblako).

Описаны Metashape Professional, предварительно сохранённый PSX и настройки `main/cloud/host_api` → `https://api.cloud.geoscan.ru`, `main/cloud/host_auth` → `https://login.geoscan.ru`. Наличие адреса API в настройке приложения **не доказывает наличие открытого SDK, документации или разрешения на произвольную интеграцию**. Для нас достаточно предусмотреть дальнейшую передачу результатов по согласованным форматам; облачная фотограмметрия не часть обязательного планировщика.

## KB378 — презентационные туры

Источник: [Виртуальные туры](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/378/cat/181/kak-sozdavat-i-prosmatrivat-virtualnie-turi).

Тур состоит из упорядоченных точек обзора с положением, направлением камеры, описанием и временем показа. Есть воспроизведение, пауза, перестановка точек и специальный вид встраивания. Для нашего демо полезны заранее сохранённые ракурсы: исходная задача → распределение → сложный переход → отчёт. Такая экскурсия по сцене должна отличаться от симуляции физического полёта.

## KB379 — производительность и ошибки визуализации

Источник: [Типичные проблемы Облака](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/379/cat/181/chasto-voznikajuschie-problemi-i-ih-reshenija).

Документация ограничивает публикацию обычных 3D-моделей свыше 100 МБ и рекомендует тайловые представления; OBJ-облака точек могут быть слишком тяжёлыми. Названы LAS/LAZ/E57/Cesium3DTiles, пример размера тайла 512 и ограничение текстур 4096 для совместимости. Это рекомендации конкретной системы, не универсальные нормативы WebGL.

Наш вывод: отображать упрощённую геометрию, подгружать уровни детализации, держать управление отзывчивым при расчёте. Численные метрики и экспорт не должны вычисляться по упрощённой картинке. Состояние отмены задачи может включать очистку, поэтому показывать его явно, а не оставлять кнопку без реакции.

## KB377 — инспекция и отчёт

Источник: [Обследование объектов](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/377/cat/181/kak-provodit-obsledovanie-obyektov-sozdavat-annotacii-i-sostavit-otchet).

Связаны точка сцены, исходное изображение, прямоугольная аннотация, тип/серьёзность и отчёт PDF/CSV. Важная оговорка: поиск снимков по точке учитывает положения/ориентации камер и калибровку, **но не препятствия и карты глубины**. Поэтому попадание точки в проекцию камеры не гарантирует её видимость.

Для нашей доказательной панели полезна связь «нарушение → участок маршрута → исходные параметры → проверка», а не внедрение автоматического поиска дефектов. Если заявим контроль видимости/окклюзий, он потребует собственного проверенного алгоритма; одного фрустума камеры недостаточно.

## KB376 — слои, измерения, профили

Источник: [Векторные слои и измерения](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/376/cat/181/kak-rabotat-s-vektornimi-slojami-i-provodit-izmerenija).

Есть точки, ломаные, полигоны, атрибуты, GeoJSON-экспорт, измерение 2D/3D-длины, площадей, объёмов и профиль высот. Для объёмов используются данные ЦМР, а не облака точек/обычная 3D-модель. Источник высот можно выбрать; после изменения геометрии зависимые результаты сбрасываются. Профиль экспортируется в CSV со столбцами широта, долгота, высота, расстояние; он не сохраняется между сессиями.

Полезно для нас: явный источник DEM, единицы, шаг выборки, инвалидирование старых результатов и экспорт данных профиля. Названия площадей в статье неоднозначны относительно описанного алгоритма проекции; не копировать эти названия как математическое определение. В нашем валидаторе дать точные формулы/CRS. Локальные и облачные редактируемые векторы не объявлены автоматической двусторонней синхронизацией.

## KB375 — настройки визуализации

Источник: [Визуализация геоданных](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/375/cat/181/kak-nastroit-vizualizaciju-geoprostranstvennih-dannih).

Описаны видимость, прозрачность, размер точек, раскраска по цвету/высоте, ограничивающий объём и трансформации локальных моделей. Для нас нужны независимые слои задания, запретов, маршрутов, покрытия, рельефа и ошибок. Скрытие слоя должно менять только отображение, а не отключать ограничение в расчёте. Любой сдвиг геометрии — новое версионированное входное значение, если влияет на расчёт, а не незаметная косметическая правка.

## KB373 — веб-просмотрщик

Источник: [Работа с веб-просмотрщиком](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/373/cat/181/kak-rabotat-s-veb-prosmotrschikom).

Описаны режимы Земля/Модель, мышь/жесты/клавиатура, сохранение ракурса, единицы, уровни качества и сравнение двух наборов ползунком. Существенные ограничения: преобразования координат не переводят высоты относительно геоида; в режиме сравнения локальные ЦМР не поддерживаются, показывается глобальный рельеф. Значит, красивое совпадение картинки недостаточно для контроля высот.

Наш UI: синхронные виды «baseline / наш план», одинаковые масштаб и время, профиль высот с указанной системой отсчёта, предупреждение об устаревших данных. Просмотрщик Облака прочитан по документации, не протестирован интерактивно.

## KB374 — общий доступ

Источник: [Как поделиться проектами](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/374/cat/181/kak-podelitsja-svoimi-proektami).

По умолчанию проект приватный. Общедоступная ссылка разрешает просмотр без входа; после выключения и повторного включения адрес остаётся тем же. Положение/ориентация камеры могут храниться в параметрах ссылки. Встроенный вид может меняться вместе с настройками проекта.

Для доказательной сдачи сохранить локальный неизменяемый пакет, не ограничиваться живой ссылкой. Публичную ссылку включать только для разрешённых данных. Географические координаты в URL — также раскрытие местоположения, а не безобидный параметр оформления.

## KB370 — роли и доступ команды

Источник: [Управление командой](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/370/cat/181/kak-upravljat-komandoj).

Разделены роль в команде и роль в каталоге; права наследуются. Более слабое прямое право не отменяет сильное унаследованное. Даже зритель может скачивать содержимое. Есть ограничения неавторизованного доступа и приглашений по доменам, отдельные полномочия владельца и администратора.

Для команды из двух человек не нужен полный аналог этой системы. Достаточны локальный рабочий режим и отдельная безопасная демонстрационная копия. Если появится сервер с несколькими пользователями, права чтения, изменения и скачивания проектировать раздельно; нельзя считать название роли доказательством запрета выгрузки.

## KB371 — организация и форматы данных

Источник: [Управление данными](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/371/cat/181/kak-upravljat-svoimi-dannimi).

Иерархия включает папки, объект с проектами разных дат, проект, группы и наборы данных. Обычный веб-проект с готовыми геоданными отличается от Metashape-проекта с PSX, исходными снимками, результатами и журналом обработки. Поддержаны GeoTIFF, векторные GeoJSON/GPKG/SHP/DXF/GML/DGN, облака точек и 3DTiles, сервисы WMS/WMTS/TMS.

Важны CRS и происхождение файлов: для облаков точек/тайлов описана выгрузка `.3tz` в геоцентрической EPSG:4978, не в градусах EPSG:4326. Есть оговорки про отличия трансформаций EPSG/PRJ. Внутри статьи остались настройки и адреса Agisoft, тогда как KB387 описывает адреса Геоскана. Это несогласованность документации; не направлять туда данные автоматически.

Наш вывод: хранить исходник, канонический план и визуальную производную отдельно; история дат не заменяет версию расчёта. Наличие поддержки GeoJSON в Облаке не превращает его в исполнимую миссию автопилота.

## KB114 — низковысотная/наземная съёмка

Источник: [Съёмка с небольшой высоты](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/114/cat/19/soveti-po-syemke-s-nebolshoj-visoti-i-s-zemli).

Рекомендации касаются ракурсов, слепых зон, перекрытия на углах фасадов, бликов, маркеров и нескольких видов важных деталей. Это отдельная задача от горизонтального покрытия площади. Не добавлять фасадную реконструкцию в обязательный объём трека без требования, но не обещать её качество по одной надирной траектории.

## KB113 — аэрофотосъёмка разных территорий

Источник: [Советы для самолётной АФС](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/113/cat/19/soveti-po-aerofotosyemke-s-bpla-samoletnogo-tipa).

Общие рекомендации — поперечное перекрытие не ниже 60%, продольное не ниже 80%, короткая выдержка, согласованное освещение. Отдельно рассматриваются лес, город, вода и горы: повторные/перекрёстные проходы, наклонные снимки, свежая модель высот, избегание бликов и малоинформативных кадров.

Числа высот для леса/гор — контекстные советы для реконструкции, **не разрешение полёта, не предел БВС и не условия ТЗ**. Фиксировать профиль качества по сценарию и подтверждать у эксперта. Оптимизация не должна выигрывать за счёт снижения качества входных данных.

## KB112 — общие требования к фотографиям

Источник: [Общие правила съёмки](https://geoscan.helpdeskeddy.com/ru/knowledge_base/art/112/cat/19/obschie-pravila-i-soveti-dlja-syemki).

Рассмотрены разрешение, фокус, модель дисторсии, ISO, выдержка, резкость, перекрытие, геопривязка, EXIF и группы калибровки. Геометрически преобразованные/обрезанные фотографии могут нарушить автокалибровку; оригиналы сохранять отдельно от миниатюр интерфейса. Однообразные, отражающие и движущиеся поверхности ухудшают реконструкцию.

Число опорных точек, параметры объектива и диафрагмы из общей статьи не универсальны для всех наших камер. Эти советы служат основанием для проверки качества, но не автоматической заменой параметров профиля камеры или требований жюри.
