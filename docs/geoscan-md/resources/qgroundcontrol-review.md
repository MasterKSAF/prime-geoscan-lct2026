## 1. Каталог возможностей

| Блок | Документированные возможности | Ограничение / значение для нас |
| --- | --- | --- |
| Plan | Точки и команды; площадная, коридорная, структурная съёмка; посадка самолёта; камера; преобразование всей миссии; профиль рельефа; статистика времени, расстояния и батарей | Набор зависит от типа БВС и прошивки; планирование офлайн требует явно выбрать их |

| Fly | Взлёт, посадка, возврат, пауза, продолжение, восстановление миссии после посадки; guided-команды | Самолёт при паузе кружит, коптер обычно висит. Emergency Stop не является безопасной посадкой |

| Телеметрия | Состояния готовности, батареи, GNSS/RTK, RSSI, ESC, Remote ID, подвес, подпись MAVLink; настраиваемые значения | Виджеты появляются при наличии соответствующих сообщений и возможностей |

| Подготовка | Прошивка, рама, датчики, пульт, режимы, батарея, ESC, моторы, параметры, PID/автотюнинг | Это операции реального управления и настройки оборудования; в исследовании не выполнялись |
| ArduPilot-specific | Failsafe, безопасность, servo outputs, Lua через MAVLink FTP, логирование, remote support | Не все страницы доступны всем типам аппаратов/версиям |
| Карты | Провайдеры, пользовательский XYZ URL, кэш, офлайн-наборы, импорт/экспорт, выбор elevation provider | Офлайн-подложка не доказывает наличие DEM, metadata и всех зависимостей |
| RTK | База/survey-in, фиксированная позиция, NTRIP, RTCM, UDP | GNSS-точность не равна полной точности съёмки или безопасному разделению |

| Диагностика | Категории app log, журнал телеметрии, сохранение исходного/изменённого плана, диагностика загрузки и metadata | Хорошая основа нашей матрицы воспроизводимости |

## 2. Что важно при построении маршрута

### Камера, рельеф и геометрия

Survey связывает размер сенсора, разрешение изображения, фокусное расстояние, ориентацию, GSD, высоту и два перекрытия. Для ручного режима задаются высота, шаг кадров и расстояние между галсами. Есть развороты вне контура, кадры на разворотах, повторная съёмка под 90° и остановка для снимка у коптера.

Документация прямо предупреждает: при отличии высоты района от home фактическое перекрытие меняется, вплоть до опасного маршрута. Terrain Follow имеет ограничения скорости набора/снижения и допуск по высоте. Ни DEM, ни визуализация сами по себе не гарантируют отсутствие деревьев, проводов и других препятствий.

Структурная съёмка в просмотренной странице заявлена для PX4 и **не поддержана ArduPilot**; старые планы Structure Scan могут требовать пересоздания. Не обещать переносимость всех complex items.

### Посадка и завершение

Fixed Wing Landing разворачивается в `DO_LAND_START`, `NAV_LOITER_TO_ALT`, `NAV_LAND`; фактическую траекторию формирует прошивка. На PX4 недопустимая геометрия посадки может быть отвергнута при загрузке/проверке миссии. Это не аналог парашютной посадки Геоскана 201.

Planned Home используется для проектирования и оценок. Actual Home устанавливается бортом при подготовке/arming. Их нужно записывать отдельно. Перенос или поворот миссии требует повторной проверки рельефа, геозон, точек старта и посадки.

### Возобновление после батареи

`Continue` и `Resume` различаются. Resume после возврата/посадки перестраивает миссию и добавляет необходимые предшествующие команды камеры и скорости. Для проверки сохраняются:

1. исходный план;
2. новый план после Resume;
3. app log;
4. telemetry log.

В нашей реализации «оставшаяся работа» должна определяться по подтверждённому покрытию/событиям, а не только индексу waypoint. Нужно проверить разрыв съёмки, повторные кадры, восстановление шага камеры и скорость входа.

## 3. Доказательства и симуляция

- TLOG-replay воспроизводит полученные сообщения и может показывать потерю связи при паузе. Это не расчёт физики и не реальный повторный полёт.
- Логи борта и принятая телеметрия различаются полнотой и частотой. Потери канала могут создать пропуски; наличие TLOG не доказывает наличие всех событий.
- Для mission/geofence/rally нужны отдельные protocol traces. Сохранённый файл, загруженный файл и действительно исполняемая миссия — разные состояния.
- Для диагностики standard modes одних MAVLink-пакетов недостаточно: важна обработка сообщений в app log.
- Программа умеет автоматически отправлять логи внешнему сервису и удалять их после загрузки. В доказательном стенде такие функции должны быть осознанно настроены; исходные доказательства не удалять, закрытые данные не публиковать автоматически.
- 3D-здания из OSM и средняя высота этажа — визуальная модель с неопределённостью, не сертифицированная карта препятствий.

## 4. Найденные расхождения документации

Ветка URL называется Stable_V5.1, но стартовая статья говорит о master/daily. Это снимок страниц, а не гарантия соответствия конкретному бинарнику.

| Расхождение | Где | Как поступаем |
| --- | --- | --- |
| AirMap как terrain source vs выбор нового elevation provider, например Copernicus | Survey/ Corridor vs Maps | Фиксируем поставщика, дату DEM, покрытие, разрешение и проверяем реальную версию |
| MKV по умолчанию vs переход на MP4 | Fly/Video vs What's New | Формат задаём явно, проверяем итоговый файл |
| Удаление MAVLink v1 vs старое описание выбора протокола | What's New vs Telemetry | Версию протокола подтверждаем handshake и runtime-тестом |
| Старая общая страница настроек vs новые специализированные страницы | General vs Fly/Maps/Telemetry | Не обещаем точные пункты UI до проверки закреплённой сборки |
| SDL2 в joystick-описании при обновлённом окружении сборки | Joystick vs developer/build documentation | Совместимость контроллера и версии проверяем отдельно |
| Preset с тем же именем может иметь другие настройки на другом ПК | Pattern Presets | Экспортируем явные параметры, проверяем повторный импорт на чистом профиле |

## 5. Решения для нашего проекта

**P0:** неизменяемый canonical plan, явные системы высот, поддерживаемый набор команд, независимая проверка, повторный импорт, фиксация версии runtime, схема evidence bundle.

**P1:** качественные 2D/3D-представления одной модели, временная шкала и карта покрытия, объяснение ограничений и сравнение вариантов, подтверждённое возобновление после остановки.

**Не расширять MVP без необходимости:** прошивка оборудования, remote support, прямое управление моторами, PID-тюнинг, физическое управление джойстиком и полная замена наземной станции.
