# Сервис планирования и распределения беспилотных авиационных работ

ЛЦТ 2026 · Задача №5 · Геоскан · Прайм Planner · Редакция 17 сентября 2026

## 01. Задача и результат {#task}

Оператор задаёт территорию, беспилотники и сенсоры, площадки, заряд, ветер и ограничения. Сервис распределяет работы, строит маршруты **с расписанием** и предлагает два варианта: раньше закончить всю работу или сократить суммарное время полётов. На выходе — понятный веб, индивидуальные KML/GeoJSON и проверяемый отчёт.

**Наша стратегия:** корректность на новом входе экспертов → измеримая эффективность → удобный 2D → воспроизводимая сдача. Это рабочий приоритет, не официальные веса оценки. Красивое демо не компенсирует нарушений. Первое место гарантировать нельзя; ML не является обязательной частью задачи.

**Уже есть:** редактор карты, коптерное распределение, две цели, временной бюджет батареи, плеер, экспорт и Docker-стенд. По прежнему [протоколу](../planner/verification.md) — 16 тестов ядра и 13 API-проверок. Нет полноценного расписания/разведения, 4D-запретов и достижимости посадки; 201, LiDAR и геофизика не готовы. Это план, не отчёт о новых реализованных функциях. Новые функции ниже ещё не реализованы. В этой редакции изменена только подпись Leaflet без декоративного флага; ядро не переписано.

**Решения пользователя 17.09:** только 2D; рабочий веб и Docker для жюри; скриншоты/скринкаст; CPU. Создание миссии — мастер вопросов, импорт области/ограничений, библиотека заданий, читаемый YAML/JSON и подтверждение рассчитанного варианта. Повторные вылеты сохраняются. Новых примеров/матрицы оценки/логов пока нет. 3D и погодный API — развитие, не зависимость.

## 04. Объём и критерии готовности {#scope}

Целимся в комплект §7.2 к 29.09, включая материалы §7.1. Сохранённое сообщение администратора от 16.09 №260 требует полное решение и презентацию; не считаем дату сдачей только макета. Точный проверяемый функциональный охват остаётся вопросом экспертам.

| Приоритет | Что готовим | Критерий |
| --- | --- | --- |
| P0 · ядро | Профили, две цели, ресурс/ветер, 4D-запреты/препятствия, разделение, достижимость посадки, экспорт | Положительный результат проходит проверки, намеренная ошибка обнаруживается |
| P0 · охват ТЗ | Пять типов работ, самолёт/коптер, раздельные базы, простой повторный вылет | Отдельные модели качества и положительные/отрицательные тесты; условный профиль не доказывает реальную совместимость |
| P0 · продукт/сдача | Качественный веб, расписание/плеер, сравнение, отчёт, Docker, документы/слайды | Новый вход доходит до экспорта без редактирования кода; чистое воспроизведение |
| Запрос команды · карта | Наглядный 2D: точки, области, маршруты, запреты, движение и шкала времени | Оператор понимает, что и где делается; подложка имеет источник/лицензию, расчёт от неё не зависит |
| P1 · усиление | Лучшее назначение; объяснение отказа с проверяемой рекомендацией | Измеримая польза тем же валидатором; не мешает P0 |
| После сдачи | 3D, точная энергетика/логи, GCS/SITL, динамическая погода, сложная зарядка, большие парки | Отдельные данные и критерии испытания |

**RGB на 2–3 коптерах — первая сквозная ступень, не замена остальных видов работ.** При отсутствии данных — явно пользовательский/демонстрационный профиль, не выдуманная характеристика Геоскана. Без согласования упрощения строка остаётся риском соответствия. Полный охват требует контрольных точек и проверки неизвестных профилей; дополнительные удобства не вытесняют требования ТЗ.

## 05. Контракты, модели и алгоритм {#algorithm}

**Сохраняем стек:** React/TypeScript, Leaflet, Zod, Turf/polygon-clipping, серверный TypeScript в существующем vinext/Vite, Node 24, Docker Compose; тесты node:test, TypeScript и Playwright. Не мигрируем весь проект и не добавляем ML без измеримой необходимости. Сначала аудит кода и регрессий, затем небольшие проверяемые изменения.

**CPU:** Ryzen 5 7430U, 6 ядер/12 потоков, около 13,8 GiB памяти ОС. Текущий Compose — 2 CPU/1 GiB; сначала замеры, затем обоснованная настройка лимитов. GPU и облачная LLM не нужны. Тяжёлый поиск изолировать от UI с учётом возможностей текущего серверного runtime.

### Контракт и единый результат

Сценарий: версия, несколько заданий с собственными областями/типами работ, дата/часовой пояс, Polygon/MultiPolygon с отверстиями, тип/качество работ, «БВС + сенсор + АКБ», старт/посадка/резервы, ветер, рельеф/препятствия, разрешённые объёмы и интервалы. У числа — единицы, источник и статус: подтверждено / допущение / неизвестно. Неизвестное не равно нулю. Скрытие слоя на карте не отключает ограничение.

Результат: идентификатор входа/плана, БВС, вылеты, время старта, координаты/высоты/скорости/времена фаз, события сенсора, ресурс, метрики и проверки. Дополнительный JSON документирует то, что не помещается в KML/GeoJSON. Карта, профиль высот, плеер и экспорт читают этот план; изменение входа/профиля/DEM делает его устаревшим.

**Обмен:** мастер и YAML/JSON описывают один строгий контракт. Геометрия импортируется отдельно из KML/GeoJSON с назначением слоя и проверкой высот. Есть библиотека, краткий/полный предпросмотр, подтверждение; версия v1 мигрируется явно. Читаемый MD — пересказ, не произвольный исполняемый текст. Подробности и защита загрузок: [мастер миссии](../planner/mission-workflow-spec.md).

### Модели и границы

| Подсистема | Решение | Проверка / граница |
| --- | --- | --- |
| RGB / MS / ИК | Для камеры вниз: отпечаток = AGL × размер матрицы / фокус; GSD = отпечаток / пиксели; шаг = отпечаток × (1 − перекрытие) | Обе оси, цикл кадров, смаз в принятом приближении, края/стыки; свои профили MS/ИК. Реальное качество снимков не доказано |
| LiDAR | Ширина/угол захвата, высота, скорость, частота и требуемая плотность/шаг | Отдельная модель. Средняя плотность не доказывает отсутствие локальных пропусков и точность облака |
| Геофизика | Высоты БВС и сенсора раздельно; рабочие линии; шаг отсчётов = путевая скорость / выходная частота | Подвес/контрольные линии — по подтверждённым параметрам. Не переносим нормы одной услуги на весь трек |
| Батарея | Временной бюджет полного заряда × доступная доля, с резервом; все воздушные фазы | Один резерв не вычитается дважды. Вдоль пути хватает на допустимое завершение; 20% — только помеченный пример |
| Ветер | Постоянный вектор; предел профиля и оценка направлений/заходов. На съёмке — допущение постоянной путевой скорости | Не выдумывать универсальное «строго вдоль/поперёк». Правило обосновать; текущую модель воздушной скорости менять только с миграцией/тестами |
| Самолёт | Защитный объём и время поворота/ожидания, скорости/набор/снижение | Оболочка проверяется целиком. Нет зависания; упрощение не подтверждает реальный полёт |
| Повторный вылет | Непересекающаяся занятость БВС, фиксированное обслуживание, явная доступность сменной АКБ | Нет нулевой зарядки/бесконечного ресурса. Сложный парк зарядников не требуется для первого варианта |

**Правила с источниками:** [исследование норм и профилей](../planner/standards-profiles-and-missions.md). Учитываем условия освещённости применимого стандарта, а не часы для всех сенсоров. Для 201 есть отдельное паспортное требование высоты над объектами; безопасное межбортовое разнесение пока не подтверждено. Батареи/времена готовности — по конкретной комплектации или явно учебному профилю. Число циклов не даёт достоверного прогноза остаточной жизни.

**Высота:** рабочая AGL и ограничения/препятствия приводятся к общей системе. Минимум — адаптер локальной сетки/DEM с датумом, NoData и границами покрытия. Синтетическая поверхность допустима для теста и помечена; геотифф и онлайн-сервис одновременно не обязательны. Несопоставимые данные дают «не проверено», не зелёный допуск. Проверяем переходы и набор/снижение; поддержание AGL автопилотом не заменяет проверку препятствий.

### Порядок расчёта

1. Проверить вход и совместимость, допустимые календарные окна работ/полётов и свежесть источников; сохранить исходную область. Недоступную часть не вырезать без отчёта: остаток работы не исчезает.
2. Рассчитать параметры сенсоров, участки/проходы, варианты направления, входа/выхода, допустимые переходы; учитывать края и швы.
3. Построить допустимый baseline, затем переносить/обменивать участки и менять порядок. Пересчитывать ресурс, посадку, расписание и обе цели совместно.
4. Развести вылеты задержками старта/коридорами; проверять сближение на пересекающихся интервалах, взлёт/посадку и оболочки. Изменение старта может изменить активность запрета.
5. Проверить достижимость хотя бы одной заданной пригодной площадки вдоль всей траектории с оставшимся ресурсом. Для дискретизации нужны консервативные оценки между отсчётами.
6. Отдельным валидатором пересчитать ограничения/качество без доверия флагам решателя. Малые эталоны и мутационные тесты нужны из-за общей геометрической библиотеки.
7. Сохранить неизменяемый план и доказательства; затем визуализировать. Эвристика не гарантирует глобальный оптимум и нахождение любого существующего решения.

**Предпочтения «ниже/выше/сторона обхода»** действуют только среди допустимых маршрутов. Облёт сверху требует известной высоты препятствия и достаточного потолка; неизвестность не даёт разрешения. Изменение времени может активировать запрет или нарушить окно съёмки — пересчитываем весь план.

**Цели:** T_project = готовность последних данных − начало проекта; T_air = сумма длительностей воздушных фаз всех вылетов. Подготовку, обслуживание и получение данных задаём явно и без двойного учёта. Ожидание на земле — не налёт, ожидание самолёта в воздухе — налёт и расход. Сначала допустимость, затем цель; обе метрики всегда видны.

**Статусы разделяем:** найдено / не найдено за бюджет / доказан конфликт / неподдержанные данные; отдельно pass/fail/unknown проверки и full/partial объёма. Согласовать новую схему с существующим API; его undetermined нельзя переименовать в реальную безопасность. flightReady:false сохраняется.

## 06. Наглядный 2D и опыт заказчика {#interface}

Geoscan — привычная компоновка **дерево → карта → свойства**, снизу время/фазы. QGC — связанные параметры камеры; Mission Planner — события съёмки. Не копируем чужие графику/код без проверки прав. Несколько дронов и сетка не новизна; ценность — распределение неодинакового парка и объяснимый результат.

| Действие | Что работает |
| --- | --- |
| Подготовить | Мастер: работы → область → дата/окна → БВС/базы/АКБ → ограничения → предпочтения → краткое/полное задание. Импорт/библиотека, источники параметров |
| Рассчитать | Прогресс, бюджет времени, отмена, ошибки у полей; тяжёлый поиск не блокирует браузер |
| Сравнить | Одинаковый вход, две цели и обе метрики, качество/ограничения; неверный план не считается выгоднее |
| Подтвердить и проиграть | Выбор варианта и явное подтверждение его версии; общая шкала, фазы/сенсор/ресурс/замена АКБ/следующий вылет. Не реальные команды |
| Разобрать | Нарушение → место/время/порог/источник; отказ → возможное изменение → проверенный перерасчёт |
| Выгрузить | Индивидуальные задания, сценарий, отчёт и доказательства одной версии; старый результат заблокирован |

**Задание → план → симуляция** — три разных объекта. Библиотека хранит версии; открытие не перезаписывает несохранённые изменения без согласия. Подтверждение привязано к хешам входа/профилей/плана, любая правка его отменяет. Текстовый комментарий не меняет расчёт. [Полная спецификация диалога, файлов и стенда](../planner/mission-workflow-spec.md).

**Карта:** сохраняем Leaflet; показываем подложку, границы работ, места старта/посадки/резерва, препятствия, маршруты и текущие позиции. Отдельные стили для «нельзя лететь», «не снимать» и «не проверено». Высоты/время ограничений доступны в свойствах и профиле — 2D не означает упрощение расчёта до двух координат.

**Подложка и офлайн:** онлайн-карта с обязательной атрибуцией либо законно полученный локальный растровый/векторный набор для выбранного участка. Поставщика и разрешение на офлайн-копию фиксируем до скачивания. Публичные растровые тайлы tile.openstreetmap.org не скачиваем массово ради офлайн — это запрещает [политика OSMF](https://operations.osmfoundation.org/policies/tiles/) (проверена 17.09); спутниковые снимки не считаем свободными автоматически. Без подложки векторные объекты/масштаб/координаты, расчёт и экспорт продолжают работать. Визуальная карта не заменяет DEM и официальный набор запретов.

**3D сейчас не делаем.** Данные плана проектируем так, чтобы позднее добавить просмотр высот без переписывания ядра; новый 3D-движок и WebGL-зависимости в первую сдачу не включаем.

Спокойная палитра, читаемые числа, легенда, текст/значки помимо цвета, видимый фокус. Приёмка 1366×768 и 1440×900, клавиатура, пустые/ошибочные состояния, карта без внешней подложки. Режим называется «модельное проигрывание», не телеметрия.

[Практический протокол](../planner/windows-gcs-study.md) и [применение GCS](../planner/gcs-transfer-plan.md): испытаны отдельные сценарии MP/QGC; Geoscan изучен по руководствам, программа была доступна до входа. Это не испытания исполнения наших миссий. Связи камеры и событий подтверждают [QGC Survey](https://docs.qgroundcontrol.com/Stable_V5.1/en/qgc-user-guide/plan_view/pattern_survey.html) и [Mission Planner camera missions](https://ardupilot.org/planner/docs/common-camera-control-and-auto-missions-in-mission-planner.html); страницы повторно проверены 17.09.

Создание, commit/push и публикация — следующий согласованный шаг, не выполнены в этом пересборе. GitHub Pages не запускает сервер расчёта; публичный стенд требует защиты API. Docker — резервный способ показа.

**Демо 4–5 минут:** загрузка задачи → мастер/предпросмотр → расчёт двух вариантов → подтверждение → вылет/замена АКБ/следующий вылет на карте → изменение ограничения и перерасчёт → индивидуальные файлы/доказательства. Цифры из этого запуска; видео не подменяет живую работу. Концепция и алгоритм объясняются коротко, детали доступны отдельно.

До срока проверить канал/формат/размеры/права загрузки, после — подтверждение получения. Слайд развития содержит реальные остаточные возможности с данными и тестами, не заменяет обязательное.

## 11. Критичные вопросы и подготовка большого промпта {#questions}

**Экспертам — три, не отправлены.** Повторные вылеты, линейная энергия и необязательность Planner уже разъяснены; пример входа/матрицу оценки ждём.

1. Какие сочетания БВС/сенсоров будут проверяться? Какие параметры качества принять для LiDAR и геофизики?
2. Какое разнесение БВС и какая система высот будут использоваться при проверке? Допустим ли явно описанный защитный объём до получения точных значений?
3. Если времена обслуживания/запас батарей не заданы, какие значения принять? Допускается ли готовность сменной АКБ вместо подробной модели зарядки?

**Позднее для публикации:** сервер/доступ/расходы и GitHub-репозиторий. Сейчас локальный веб, Docker, CPU, 2D, мастер/библиотека и читаемые задания определены; новых данных экспертов нет. Инженерные параметры не перекладываем на пользователя.

[Подготовка промпта](../planner/prompt-preparation.md) и [спецификация мастера](../planner/mission-workflow-spec.md) задают следующий этап. Переписывание ядра по новому промпту ещё не начато; минимальная правка подписи карты выполнена отдельно.
