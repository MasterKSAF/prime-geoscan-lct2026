# Рабочий цикл и проверка интерфейса · 19.09.2026

Пошаговая инструкция для текущего UX планировщика. Это **сценарий проверки**, не отчёт о прохождении тестов и не обещание конкурсных баллов. Расчётное ядро — 0.3.0, формат задания — 2.0. Исторические результаты 17–18 сентября относятся к своим срезам.

[Запуск и общие проверки](../../README.md) · [Сценарии и входные файлы](scenarios.md) · [Комплект для экспертов](submission/README.md)

## Три разных раздела

| Раздел | Что хранится | Что означает действие |
| --- | --- | --- |
| **Сценарии** | Девять учебных примеров | Открытие переносит пример в редактируемое задание после предпросмотра; это не запуск |
| **Сохранённые задания** | Исходные миссии: область, работы, флот, батареи и ограничения | «Сохранить» записывает задание; «Сохранить как» создаёт отдельный ID. Для переноса нужны JSON/YAML или резервная копия библиотеки |
| **Мои миссии** | Подтверждённые снимки модельного выполнения, очередь и история | «Поставить в план» сохраняет снимок. «Начать симуляцию» запускает модель вручную; «Открыть снимок» восстанавливает его для просмотра |

Черновик в редакторе, сохранённое задание и его выполнение — не одна запись. Одно задание может иметь разные подтверждённые выполнения. Изменение входа требует нового расчёта и подтверждения, а прежний снимок истории остаётся неизменным.

## Основной показ: 10–15 минут

Используйте отдельный профиль браузера. Откройте [локальный стенд](http://127.0.0.1:3016/planner); адрес 3015 используется только при локальном dev-запуске.

| Шаг | Что сделать | Что проверить |
| --- | --- | --- |
| 1. Пример | «Сценарии» → «Автовыбор БВС: время, налёт и баланс» → «Открыть сценарий 1» → «Заменить текущее задание» | Видны имя/ID, одна RGB-работа, участок 0,42 км², три профиля БВС. До подтверждения ничего не выполняется |
| 2. Карта | «Показать всю область», выбрать работу и БВС, передвинуть указатель по карте | Область и маршруты читаемы; координаты подписаны как широта/долгота WGS84. Кнопка «Подложка» выключает только внешние тайлы, не геометрию задания |
| 3. Ввод геометрии | «Нарисовать область работ», поставить 3–4 точки, открыть «Координаты вершин · WGS84», нажать «Убрать точку», затем Esc | Видны вершины и черновой контур; Esc сохраняет исходную область. Для замены области повторить ввод и явно нажать «Применить контур»; после такой замены нужен новый расчёт |
| 4. Флот и ветер | На шаге «Ресурсы» выбрать «Автовыбор всей группы». Открыть «Ветер» на карте; прочитать подсказку `i` | Автовыбор разрешает алгоритму выбирать из подходящих профилей, а не обещает назначить все БВС. Ветер введён в миссии; стрелка показывает движение воздуха, а «от» — его источник |
| 5. Расчёт | «Рассчитать варианты» → «Сравнить и объяснить варианты» | Сравниваются одинаковые входные данные. Есть два обязательных критерия и, если найден, «Баланс». Подсказки объясняют время, налёт, покрытие, вылеты и остаток АКБ |
| 6. Подтверждение | Выбрать допустимый вариант → «Проверить и подтвердить» → прочитать проверки/допущения → отметить согласие → «Подтвердить для симуляции» | Неизвестные проверки видны. Красный или неполный план не получает подтверждение. Качество — обязательное условие, не четвёртый вариант оптимизации |
| 7. Очередь | «Поставить в план» → «Мои миссии» | Появилась запись с собственным ID выполнения, выбранным планом и ревизией. Реальное время старта из задания само по себе ничего не запускает |
| 8. Выполнение | «Начать модельное выполнение» в журнале либо «Начать симуляцию» на основном экране; выбрать скорость ×100/×300 и БВС | Движение, события, высота и заряд следуют одному сохранённому плану. Время увеличивается; одновременно работает один выбранный модельный симулятор |
| 9. Пауза и просмотр | «Пауза», затем «Мои миссии» → «Открыть снимок». Передвинуть ползунок и нажать «В начало симуляции» | Просмотр можно перематывать, но сохранённая история не откатывается. «Возобновить модель» продолжает сохранённое выполнение, не запускает его из положения ползунка |
| 10. Доказательства | Выгрузить «Доказательства», «План JSON», GeoJSON/KML и исходное задание JSON/YAML | Evidence содержит вход/план/проверки/хеши. JSON/YAML задания можно загрузить обратно; GeoJSON/KML результата не является проверенной командой автопилота |

Чтобы не менять исходный показ при проверке рисования или параметров, сначала сохраните копию задания. Изменение геометрии может сделать пример неразрешимым — это повод изучить отказ, а не скрывать его.

## Точечные проверки нового UX

- **Темы:** выбрать «Тёмная» и «Светлая»; проверить формы, таблицы, окна, легенду и панель карты. Обновить страницу — выбор сохраняется. «Как в системе» должен реагировать на смену системной темы. При запрете localStorage выбор работает в текущем сеансе с явным предупреждением о несохранении. Цвета тайлов не инвертируются.
- **Подсказки:** навести на `i`, перейти к нему клавишей Tab, нажать Enter/клик. Esc закрывает подсказку, а не лежащее под ней окно. Текст в таблице сравнения не должен обрезаться границами окна; проверять также при ширине 390 px.
- **Направление ветра:** при 0° ветер идёт с севера на юг, при 90° — с востока на запад. При скорости 0 м/с показывается штиль. Это один постоянный вектор на область и окно, не фактическое наблюдение и не прогноз.
- **Отказ тайлов:** выключить «Подложка» или проверить сетевую ошибку в отдельном QA-сеансе. Контуры, выбор объектов и расчёт должны оставаться доступны; ошибка картографического провайдера не должна выдавать геометрию за отсутствующую.
- **Быстрая пауза/возобновление:** несколько раз остановить и возобновить модель, в том числе во время записи контрольной точки. Сохраняемое время не уменьшается; повторные клики не создают скрытый второй таймер или ошибочную повторную паузу.
- **Смена задания/варианта:** во время модели сменить вариант или открыть другое задание. Старое выполнение должно остановиться и сохранить фактическое модельное время; новый неподтверждённый план не должен стартовать. Изменение во время асинхронной команды не должно создавать неожиданный запуск.
- **Перезагрузка:** поставить паузу, записать время в журнале, обновить страницу и открыть снимок. Автовозобновления нет. Если после аварийного закрытия остался статус модельного выполнения, сначала явно выбрать «Зафиксировать паузу», затем «Возобновить модель». Работа другой вкладки не предполагается остановленной автоматически.
- **Несовместимые выполнения:** создать пересекающиеся по времени записи с теми же ID БВС. Запуск должен объяснить конфликт. Для исправления изменить и пересчитать новое задание либо явно отменить мешающую запись; отмена не удаляет историю.
- **Другие вкладки:** после изменения журнала в другой вкладке старая команда должна показать конфликт ревизий. «Обновить журнал» перечитывает состояние; скрытого повторения команды с новой ревизией нет.
- **Отрицательные сценарии:** «Отказ: ветер выше предела» и «Отказ: недостаточный ресурс» должны объяснять отсутствие полного допустимого плана. Их нельзя подтвердить или превратить в успешное выполнение.

## Что означают состояния

`В очереди` → явный запуск → `Модельное выполнение` → `На паузе` / `Завершено в модели`. Отмена переводит незавершённую запись в `Отменено` и сохраняет её. Завершённые и отменённые записи не переписываются новым запуском.

Контрольная точка сохраняется не чаще одного раза примерно в **2 секунды реального времени**; пауза и конец плана сохраняются отдельно без этого ограничения. При скорости ×300 две реальные секунды — до 600 секунд модельного времени. Аварийное закрытие страницы может потерять незаписанный хвост; восстанавливается последняя **успешно записанная** точка, не предположенное время работы браузера после закрытия.

Состояния БВС «Подготовка», «Обслуживание», «Зарядка», «Назначенные работы завершены» вычислены из данного снимка. Они не подтверждают реальную исправность или готовность к другой миссии. «В подборе» означает разрешение участвовать в поиске, а не физическую готовность к взлёту.

## Ограничения, которые нельзя скрывать

- Один активный модельный симулятор; это не диспетчеризация нескольких реальных миссий и не контроль внешнего воздушного движения.
- Журнал хранит до **20 локальных снимков**, без автоматического удаления старых записей. Отмена не освобождает место. Очистка данных браузера удаляет локальную историю; операция очистки не входит в демонстрационный сценарий.
- Хранилища привязаны к браузеру и адресу. Порты 3015/3016 и другие профили имеют разные библиотеки. Перенос исходного задания JSON/YAML не является восстановлением журнала его выполнений.
- Нет живой телеметрии, команд реальным БВС, метеосервиса, разрешений на полёт и фонового запуска по реальным часам.
- Карта — подложка и координатные слои. Нет DEM или подтверждённого перехода между реальными AGL/AMSL. Ветер постоянный, энергия модельная, физический износ батарей не вычисляется.
- Хеши связывают снимок и подтверждение, но не являются цифровой подписью диспетчера. Все сохраняемые выполнения проходят повторную модельную проверку; `unknown` остаются неизвестными.

## Техническое воспроизведение

Из корня проекта после `npm ci`; полный набор — `npm run test:planner`. Отдельные тесты новых частей:

```powershell
node --experimental-transform-types --test tests/mission-theme.test.ts tests/mission-guidance.test.ts tests/mission-map-lifecycle.test.ts tests/mission-operations.test.ts tests/mission-operations-hook.test.ts
```

Скачанный evidence проверяется отдельно:

```powershell
New-Item -ItemType Directory -Force output/ux-review-2026-09-19 | Out-Null
npm run verify:evidence -- 'путь/mission.evidence.json' 'output/ux-review-2026-09-19/evidence-check.json'
```

Перед командой замените путь на фактический файл. При сохранении нового отчёта используйте отдельный каталог, не перезаписывайте исторические проверки.

Для результата проверки записать: версию коммита/ядра, входной сценарий, шаги, фактический статус, остаточные `unknown`, снимки светлой/тёмной темы, карту с координатами, сравнение, журнал до/после паузы и результат повторной проверки evidence. Один успешный снимок экрана не заменяет проверку жизненного цикла.
