# API v2 и воспроизводимость

## Дополнение: предполётный уход и новые профили

`POST /api/planner/missions/contingency` принимает строго `{document, candidate}`. Максимум 2 МиБ UTF-8, передача тела до 5 секунд, один анализ одновременно, мягкий бюджет вычисления 5 секунд. Вход и полный кандидат проверяются заново; неизвестные поля кандидата не сертифицируются. Протокол `controlled-abort-interval-v1` возвращает хеши, полноту проверенных интервалов, отдельные маршруты/исходный коридор без съёмки, предел задержки до опорной точки и причины неполной проверки. `certified_model` относится только к управляемому прекращению при исходных условиях. Сбой вычисления/лимит не равен успеху.

Интерфейс: «Миссии → отчёт выбранного запуска → Анализ → Возврат из любой части маршрута». Отчёт скачивается с исходным заданием и кандидатом; повторная проверка: `node --experimental-transform-types scripts/verify-mission-contingency.ts bundle.json new-report.json`.

У `Vehicle` доступны необязательные `maxAirspeedMps` и `fixedWingProfile`; старые файлы не получают эти значения автоматически. [Модель 201 и публичный пример](fixed-wing201-implementation-2026-09-20.md). Предел воздушной скорости не тождественен заданной путевой скорости съёмки.

Экспорт `*.photo-coverage.geojson` содержит ожидаемые отпечатки на плоскости (`acquiredData=false`). `*.delivery-manifest.json` описывает модельный результат и ожидаемые материалы, не утверждает передачу или приёмку реальных файлов.

## Адреса и вход

С 21.09 необязательное `jobs[].window: {start, end}` задаёт отдельный период работы (ISO 8601 со смещением). Период должен лежать внутри общего `window`; весь вылет и посадка должны находиться внутри него. Поле отсутствует в старых документах без автоматической миграции хеша. UI и формат отчёта о запуске: [обновление диспетчера](dispatcher-interface-2026-09-21.md).

- GET `/api/planner/health` — версии движков, `flightReady:false`.
- POST `/api/planner/missions/solve` — документ `schemaVersion: "2.0"`.
- POST `/api/planner/solve` — прежний v1 для диагностики, не новый рабочий цикл.
- GET `/api/planner/weather` — прогноз для участка/окна; [контракт, ограничения и происхождение](weather-and-workspaces-2026-09-19.md). Снимок применяется явно через опциональное поле `weather`.

V2: `Content-Type: application/json`, до 200 КиБ (204 800 UTF-8 байт), строгая [JSON Schema](contracts/mission-v2.schema.json). Лимит общий для файлов и API. Код дополнительно проверяет ссылки и уникальность ID, даты, высоты, IANA-пояс, окно до 7 суток, геометрию. Координаты: долгота/широта WGS84; расстояния/высоты: метры; скорость: м/с; относительное время: секунды.

```powershell
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:3016/api/planner/missions/solve' -ContentType 'application/json' -InFile 'docs/planner/contracts/example-1km2.json'
```

## Ответ

Новые расчёты требуют `planning.safetyPolicy: "continuous-occupancy-v1"`. Без него API возвращает `422 SAFETY_POLICY` после проверки формата и размера; редактор явно переводит рабочий черновик на текущую политику. Старые документы читаются для истории без добавления поля и изменения хеша, но их запуск/возобновление требует пересчёта. Политика включает наземную занятость, единую проекцию разнесения, временной запас 4D и внутренний защитный отступ воздушной зоны. Это версия модельной проверки, не сертификация.

HTTP 200 не означает успех миссии. Ответ: document, inputHash, engineVersion, createdAt, computationMs, warnings и два candidates.

В ядре **0.3.0** два обязательных `candidates` сохранены. Дополнительный `recommendation` появляется только при полном допустимом плане. Внутри — `candidate` с ID `balanced`, политика `balanced-normalized-v1`, веса 0.5/0.5, диапазоны нормализации, оценка, число найденных вариантов, признаки совпадения с основными планами и объяснение. Поле `objective` кандидата сохраняет исходную цель генерации для совместимости; принадлежность к режиму «Баланс» определяется ID и политикой, а не новым значением enum.

Формула: `0.5 × norm(makespanSec) + 0.5 × norm(flightTimeSec)`. Диапазоны берутся из найденного допустимого пула; нулевой диапазон даёт 0. Сначала полнота и ограничения, затем компромисс; при равенстве — больший остаток, меньше вылетов и детерминированный порядок. Это не доказанный глобальный оптимум и не модель физического износа. Повторяющийся маршрут не выдаётся за отдельную альтернативу.

Необязательное поле входа `environment`: `cloudBaseM` (число или null), `cloudClearanceM`, `visibilityM` (число или null), `minVisibilityM` (число или null), `source`. Все метры; постоянные условия на всё окно, ручной ввод. Облака задаются в общей локальной системе высот миссии, **не AGL/AMSL**. Потолок равен границе облаков минус запас; проверяется каждая фаза. Если задан минимум видимости, неизвестная или меньшая видимость блокирует план. Неизвестная граница облаков/незаданный минимум отражаются как unknown. Отсутствующий объект сохраняет прежнее поведение и хеши старых заданий. Прогноз и оптимальный выбор высоты не добавлены.

| Статус | Смысл |
| --- | --- |
| feasible_model | Полный план прошёл обязательные проверки объявленной модели, не реальный допуск |
| partial | Часть обязательной работы не выполнена; подтверждать нельзя |
| not_found | Ограниченный поиск не нашёл план; не доказательство отсутствия решения |
| invalid | План не прошёл проверку |
| unsupported | Конфигурация не поддержана, не подменяется другой физикой |

Sorties содержат IDs работы/БВС/батареи, фазы, скорости, высоты и модельный заряд. Время отсчитывается от window.start. durationSec — воздушное время; makespanSec — до последней посадки с ожиданиями. Events — расчётные события, не телеметрия. JobCoverage сохраняет площади, покрытие и выбранный bearingDeg каждой работы.

Ошибки HTTP: 400 — JSON/схема; 403 — Origin; 408 — медленное тело запроса; 413 — размер; 415 — Content-Type; 422 — семантика/расчёт; 429 — занят процесс. Модульный флаг занятости не заменяет очередь, авторизацию и защиту публичного сервиса. **API не выставлять в публичную сеть.**

Отмена в браузере прекращает ожидание и применение ответа, **не гарантирует мгновенную остановку серверного CPU**. Бюджет проверяется между конечными попытками; отдельный тяжёлый геометрический шаг может закончиться позже. Это не жёсткое realtime-ограничение.

## Проверка доказательств

Пакет evidence.json: исходное задание, кандидат, хеши, подтверждение при наличии, GeoJSON/KML и запрос для повторения. GeoJSON хешируется как канонический JSON, KML — по точным UTF-8 байтам. SHA-256 связывает версии, не доказывает физическую достоверность.

```powershell
npm run verify:evidence -- 'путь-к-пакету.evidence.json' 'путь-к-отчёту.json'
```

Валидатор заново строит контекст из входа, проверяет направление полос, траектории, ресурс, очереди батарей, время, зоны, непрерывную сепарацию, покрытие, метрики и экспорт. Сохранённым pass не доверяет. Код возврата 1 — нарушение; 0 — прохождение объявленной модели с оставшимися unknown. Общая геометрическая библиотека означает, что это отдельный проход, но не полностью независимый внешний оракул.

Сохранять lockfile, исходное задание, хеши исходников, digest Docker и фактический отчёт. При ограниченном времени поиска более медленный CPU может рассмотреть меньше кандидатов; оптимальность не заявлена.

## Дополнительные необязательные поля диспетчера (21.09)

- `jobs[].inheritsFrom`: ID участка того же вида работ. Значения параметров материализованы в документе; сервер проверяет их согласованность с источником. Цепочки и циклы наследования запрещены. Геометрия и название участка не наследуются.
- `bases[]`: `{id, name, coordinate}`, постоянные ID и названия площадок. То же поле необязательно в `prime-fleet/1.0`; старые входы остаются читаемыми.
- `revisionSource`: ID и хеш закрытого исходного запуска, корневой ID миссии, модельная контрольная точка, причина и покрытие по участкам. Перед стартом связь сверяется с локальным журналом: неизвестный/изменённый родитель и подмена покрытия отвергаются. Импорт такого файла без исходной истории не предоставляет разрешения на запуск.
- `prime-run-report/1.revisionHistory`: проверенная цепочка исходных запусков. У старых отчётов поле отсутствует. Экспорт и CLI перепроверяют связи и контрольные точки, не только верхний хеш.

Схема и примеры: `npm run export:mission-contract`. Модельная история не является бортовым журналом или электронной подписью оператора.

## Внешний KML препятствий (22.09)

Необязательное поле `obstacleLayer` содержит версию `geoscan-kml-horizontal/1`, `filename`, неизменный `sourceText`, `bufferM`, `lineHalfWidthM`, `policySource`. Отдельный браузерный каталог переиспользуется между миссиями; документ переносит собственный снимок, чтобы сервер и CLI не зависели от IndexedDB оператора. Изменение источника или отступов меняет хеш входа и отменяет прежнее подтверждение.

- `POST /api/planner/missions/solve-with-obstacles`: тот же контракт миссии/ответа; общий лимит 12 МиБ, KML 8 МиБ, основная миссия без вложения по-прежнему 200 КиБ. Обычный `/solve` сохраняет лимит 200 КиБ.
- `/analyze` и `/contingency`: для вложения нужен `x-prime-obstacles: 1`; общий лимит 14 МиБ, основной запрос без вложения по-прежнему 2 МиБ. Заголовок не ослабляет проверку схемы/геометрии.
- Поддерживаются Polygon и LineString. Высоты сохраняются, но обход консервативно горизонтальный на всех высотах. DEM и преобразование вертикальных систем не выдумываются.
- Полный каталог сохраняется. Поиск локальный: 80 релевантных объектов, прежние бюджеты геометрии и 10 миллионов пар сегмент–объект для итогового контроля. Превышение — отказ, не усечение слоя.
- ZIP отдельной миссии проверяется: `node --experimental-transform-types scripts/verify-mission-archive.ts <archive.zip>`.

Подробности: [инструкция и приёмка](obstacle-layer-implementation-2026-09-22.md).
