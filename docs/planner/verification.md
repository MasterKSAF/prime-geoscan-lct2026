Проверено 15 сентября 2026 года. Это доказательства работы программной модели, **не полётные логи, не сертификация безопасности и не полное выполнение ТЗ**.

- Адрес: `http://127.0.0.1:3016/planner`.
- Docker Compose: `compose.planner.yaml`, образ `prime-planner:local`.
- Проверенный image ID (`docker image inspect`): `sha256:d1633e8c9e2d4759be552452462e7927c9671446897474dac4f12de69786e071`.
- Контейнер работает от пользователя `node`, состояние `healthy`; порт доступен только на локальном компьютере.
- SHA-256 пяти файлов ядра и `package-lock.json` внутри контейнера совпали с [машиночитаемым отчётом](../../output/planner-docker-verification/report.json).
- Исходный рейтинг ЛЦТ на `/` сохранён; новая рабочая страница — `/planner`.

Проверка браузером через Playwright выполнена на собранном Docker-стенде:

1. Загрузка карты, начального сценария и серверного результата.
2. Запуск и пауза проигрывания: модельное время действительно меняется.
3. Переключение критерия: прежние маршруты скрываются, экспорт блокируется до пересчёта.
4. Ветер 20 м/с: понятный отказ, HTTP 422; возврат к 3 м/с снова позволяет расчёт.
5. Отключение картографической подложки не препятствует вычислению маршрутов.
6. Импорт сохранённого сценария и повторный расчёт.
7. Последовательное скачивание доказательств и KML: уведомление не перекрывает управление.
8. Экран 1600×1050 и мобильный 390×844: на мобильном `scrollWidth = innerWidth = 390`, горизонтального переполнения нет. По ТЗ основная платформа — ПК.

В журнале этого сценария один ожидаемый HTTP 422 от теста недопустимого ветра. Успешный сценарий не выдал ошибок JavaScript. Старые отладочные трассы с перезапусками не считаются чистым доказательством финальной версии.

## Контрольный расчёт

Все координаты участка, ветер и рабочие энергетические бюджеты — учебный сценарий. Нельзя трактовать их как разрешение полёта или измеренные характеристики конкретного комплекта.

В UI покрытие округляется до 100%; точное значение хранится в отчёте. Это **не 100% исходного участка**, не подтверждённое качество снимков и не запас точности геометрии. Базовый маршрут для этого сценария оказался невыполнимым — процент улучшения не заявляется. Проверка «не хуже baseline» выполнена отдельно на тестовом сценарии, где baseline выполним.

Эти ограничения перечислены в [матрице ТЗ](implementation-status.md); данные для следующего этапа запрошены в [подготовленном письме экспертам](expert-request.md), которое пока не отправлялось.
