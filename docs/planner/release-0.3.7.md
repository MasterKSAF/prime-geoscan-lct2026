# 0.3.7 — группа БВС, срок, налёт и ресурс до ТО

Рабочая версия по уточнениям экспертов от 23.09.2026. Не заморожена и не опубликована. Презентационное видео не создавалось.

## Что изменено

1. **Лимит группы.** В редакторе «Лимит БВС»: автоматически либо не более N. Считаются разные ID за всю миссию, а не максимум одновременно летящих. Повторные вылеты того же аппарата не расходуют новое место. Ограничение проверяется и решателем, и независимым валидатором `FLEET_LIMIT`.
2. **Срок и состав.** «Завершить миссию до» задаёт жёсткий конец окна. Поиск пробует в том числе группы до 1/2/3 аппаратов. В подробном сравнении показаны найденные полные планы по лимитам. «Не найдено» не значит «невозможно», «не проверялось» не значит «не выполнимо».
3. **Цели.** «Быстрее закончить» и «Меньше налёт» сохранены. Вместо произвольного 50/50 — «Уложиться в срок»: наименьший налёт среди найденных допустимых планов при сроке и N. При равенстве — раньше завершение, больший запас, меньше вылетов, стабильный ключ. Совпавшие маршруты не выдают за три разные выгоды.
4. **Налёт.** Отдельно съёмка, переходы/возврат, манёвры и ожидание в воздухе. Ожидание на земле влияет на время завершения, но не на налёт. Налёт не является измеренной физической деградацией; штраф за взлёт не придуман.
5. **ТО.** Счётчики полётов и секунд налёта с последнего обслуживания. 201 — 80 полётов, 801 — 160 часов по ответу экспертов; Gemini — 160 часов по РЭ от 28.05.2026, с. 9. Для Gemini повторное применение интервала после ТО — консервативная политика стенда, а не дословное требование руководства. Гарантийный срок не подменяет ТО. План, превышающий известный ресурс, отвергается. При неизвестном счётчике нет выдуманного нуля. Демонстрационный ноль имеет источник `simulation`.
6. **Состояние и объяснения.** Выполнение накапливает наработку от неизменного снимка; повторная контрольная запись не увеличивает её повторно. Возврат добавляет время, но не новый взлёт. Замена батареи не сбрасывает ТО. В парке можно отдельно внести наработку; уменьшение требует подтверждения обслуживания. При отказе видны подсказки про лимит/срок/ТО. Добавление БВС, изменение срока и батареи остаются гипотезами до повторного расчёта.
7. **Доказательства и показ.** В ZIP и JSON-отчёте — ограничения, выбранные ID, срок, запас времени, фазы налёта и прогноз наработки. В HTML отчёта — краткая таблица. Презентация использует обязательные исходные слайды 7–11; неподтверждённые сведения о команде не выдуманы.

## Где проверить

- Редактор → Миссия: лимит и срок; затем «Рассчитать варианты».
- «Подробное сравнение»: «Сколько БВС нужно к сроку», «Из чего складывается налёт».
- Парк БВС → Доступность → Наработка и ТО.
- Отчёт → Все проверки / Доказательства ZIP. В архиве: `data/report.html`, `data/analysis/resources.json`, неизменный вход, план, проверки и журнал.

```powershell
npm run typecheck
npm run test:planner
node --experimental-transform-types --test tests/mission-resources.test.ts tests/mission-comparison.test.ts tests/mission-alternatives.test.ts
node --experimental-transform-types scripts/verify-mission-archive.ts "C:/path/mission.evidence.zip"
```

## Границы

- Поиск ограничен временем и эвристиками: нет обещания глобального оптимума или доказанно минимальной численности.
- Оценка ТО по счётчикам, не техническая диагностика узлов. Для неизвестного типа нужен отдельный регламент.
- Модельные камера, погода и телеметрия не превращаются в физические измерения.
- Старые снимки не переписываются: для нового ядра нужны новый расчёт и подтверждение. Отключение проверок ради запуска не применяется.
- Презентации до сдачи нужны точное название команды, роли и контакты участников, проверка владельцем. Доступ к GitHub и официальная подача не выполнялись.

Результаты текущих проверок фиксируются отдельно в `release-0.3.7-verification.json`; старые отчёты версий 0.3.4–0.3.6 не выдаются за проверку 0.3.7.

### Проверенный срез

- 600/600 тестов на Windows и в Linux при Docker-сборке, проверка типов и линтер затронутых модулей.
- 47 браузерных проверок: N=1/2/3, сохранение ТО, полное выполнение Демо 1 и 2, отказ Демо 3, экспорт ZIP/JSON/MP4, групповой возврат и ветер выше предела.
- ZIP завершённой Демо 2 проверяется отдельно на Windows и Linux. Отказ Демо 3 и оба аварийных события воспроизводятся без превращения отказов в успешные полёты.
- Runtime 0.3.7: 269 проверенных файлов совпали с исходниками. Это проверка выбранных байтов, не воспроизводимый хеш сборки из чистого клона.
- Подсказка о замене батареи теперь выбирает только совместимый аппарат, разрешённый для работы; чужие разряженные БВС не занимают первые рекомендации.
