# Карта и колода миссий · 24 сентября 2026

Рабочая версия с ядром **0.3.8**, контрактом **2.0**. Это реализация [согласованной очереди](history/2026-09-24/PENDING-UI-CHANGES.md), не заморозка и не новый комплект для подачи. Коммит, push, открытие доступа, презентация и видео в этой работе не выполнялись.

## Что сделано

| Где | Изменение |
| --- | --- |
| Миссии | Три исходных примера и постоянная карточка загрузки. Каждый импорт добавляет собственную миссию. Есть редактирование, скачивание, удаление и переход к запуску. |
| Импорт | Сохраняются ID, геометрия, погода и условия файла. Повторный ID требует выбора существующей карточки или новой копии. Конфликт общего БВС показывает различия профиля/заряда/базы и требует явного решения. |
| Редактор → Данные миссии → Объекты карты | Общая точка управления базами, границей полётов, запретами и запасными площадками. Быстрый вход — кнопка «Объекты карты» на карте. Участки съёмки остаются у выполняемой работы. |
| Базы и посадка | Добавить базу нажатием на карту, выбрать аппараты, сохранить. Можно перенести, переименовать, удалить с переназначением. Для нескольких БВС сохраняются отдельные безопасно разнесённые модельные точки стоянки. |
| Граница полётов | Нарисовать, изменить вершины, подтвердить или отменить правку, загрузить GeoJSON/KML, очистить и восстановить. При редактировании карта охватывает границу. Без неё расчёт недоступен. |
| Запреты и препятствия | Понятные действия рисования и импорта. Загрузка запрета больше не предлагает незаметно заменить участок съёмки. Для нарисованной зоны доступны имя, период, высоты и удаление. После её рисования точки участка не включаются в редактирование. |
| Каталоги экспертов и образцы | Сохранены специализированные импортеры полных KML; добавлены маленькие GeoJSON границы, запрета и запасной площадки. Они обозначены как модельные образцы. |
| Выполнение | До расчёта — одно действие «Рассчитать план» вместо пустого проигрывателя. Произвольный ID работает с собственным запуском и журналом. |
| Отчёт | Отдельные действия: открыть отчёт, проверки, маршруты KML/GeoJSON, доказательства ZIP. Дополнительные форматы собраны отдельно. Статус плана, выполнение проходов и покрытие территории не смешиваются. |
| Общая подача | Убран повторный срок, технический дубль управления парком, неверное «Ошибок нет» при ограничениях проверки. Инструкции приведены к фактическим кнопкам. |

## Что защищено

- Перенос базы согласуется с общим состоянием парка и затронутыми черновиками; заряд не сбрасывается. Все проверки изменения выполняются до атомарной записи группы аппаратов.
- Подтверждения изменённых планов отменяются. Старый расчёт доступен в отчёте как предыдущий, но не разрешает новый запуск.
- Сохранённые запуски и их доказательства не переписываются: для редактирования создаётся копия. Удаление запуска не равно удалению исходной карточки.
- Перемещение общего парка при незавершённых запусках намеренно блокируется. Это консервативное ограничение стенда: изменение маркера не имитирует перелёт занятого БВС.
- Места стоянки проверяются относительно допустимого контура, препятствий, буферов и взаимного расстояния. Временные ограничения для постоянной базы учитываются консервативно. Проверки всего маршрута после переноса остаются обязательными.
- До **50 карточек / 80 МиБ** в сессии, до **трёх активных запусков**, до **20 записей истории**. Завершённые и отменённые запуски не занимают активные слоты. Ограничения хранилища не обходятся молчаливым удалением.
- После перезагрузки страницы начинается чистая демонстрационная сессия. Перед обновлением сохраните нужные JSON и доказательства; «Начать с нуля» требует подтверждения.

## Проверки

Полная Docker-сборка выполняет typecheck, **621 автоматический тест** и сборку приложения. Отдельно проверены линтером изменённые компоненты, логика, новые тесты и браузерные сценарии. Это не утверждение о чистоте всех посторонних скриптов общего рабочего каталога.

На собранном стенде `127.0.0.1:3016`, в изолированной сессии Playwright:

- **34 проверки объектов и карточек:** пять импортов, восемь миссий плюс загрузка, повреждённый файл, дубликат, удаление копии; очистка/восстановление/перетаскивание и отмена границы; создание базы для двух БВС, сохранение заряда, реальный повторный расчёт, синхронизация другого черновика, безопасное удаление; контекст импорта и узкий экран.
- **20 проверок расчёта и выгрузок:** все три исходных примера; Демо 2 доведено до завершения; произвольный импортированный ID рассчитан, подтверждён и выполнен; отдельные маршруты и полные ZIP скачаны через интерфейс.
- **18 проверок слоёв и оформления:** маленькие GeoJSON действительно загружаются с нужной ролью; удаляются запасная площадка и запрет; рисуется замкнутый запрет; проверены светлая/тёмная темы и возврат из отчёта.
- Четыре скачанных ZIP независимо проверены, включая контрольные суммы и модельные ограничения. Содержимое отдельных KML/GeoJSON побайтно совпало с соответствующими маршрутами полного архива.

В автоматическом наборе отдельно пройден путь **полный JSON → расчёт → независимая валидация → архив → повторная проверка** для RGB, MS, IR, LiDAR и геофизики. Неподходящий сенсор не получает успешный план. На копии Демо 2 операторский запрет всего района на всё окно даёт отказ; его снятие и пересчёт возвращают допустимый модельный план. Исходный экспертный сценарий не изменяется ради этой проверки.

Для Демо 2 два критерия дают очень близкое время завершения — это не ошибка и не доказательство трёх разных выгод. Ограниченный поиск не объявляется глобально оптимальным для любого входа.

## Как повторить

Использовать отдельную браузерную сессию: сценарии проверки нажимают **«Начать с нуля»** и создают тестовые миссии. Не запускать их в рабочем профиле с несохранёнными данными.

```powershell
docker compose -f compose.planner.yaml build planner
docker compose -f compose.planner.yaml up -d --no-build planner
npx --yes --package @playwright/cli playwright-cli -s=queue-check open http://127.0.0.1:3016/planner
npx --yes --package @playwright/cli playwright-cli -s=queue-check run-code --filename=scripts/checks/queue-20260924-browser.js
npx --yes --package @playwright/cli playwright-cli -s=queue-check run-code --filename=scripts/checks/queue-plans-20260924-browser.js
npx --yes --package @playwright/cli playwright-cli -s=queue-check run-code --filename=scripts/checks/queue-layers-20260924-browser.js
node --experimental-transform-types scripts/checks/verify-queue-downloads.ts queue-prod
```

Команда браузерного инструмента может вернуть код процесса 0 даже при `### Error`: проверять JSON `passed`, список `checks` и `errors`, а не только exit code. Выгрузки не являются окончательным пакетом подачи.

Локальные результаты: `output/planner-queue-20260924-build.log`, `output/playwright/queue-prod-objects.log`, `queue-prod-plans.log`, `queue-prod-layers.log`, `queue-prod-download-verification.json`; ZIP и скриншоты лежат там же.
