# Препятствия экспертов: реализация, проверка и границы

Дата: 22.09.2026. Это отчёт о новом приращении стенда, **не обновлённый комплект для сдачи**. Презентация и публикация репозитория в эту итерацию не входят.

## Что появилось

1. Отдельная загрузка большого KML препятствий: Polygon и LineString, исходные высоты, отчёт по каждому объекту, проверка геометрии, отмена обработки.
2. Переиспользуемый локальный каталог и слой карты: поиск по имени/ID, фокус на объекте или всём слое, переключатель видимости. Скрытие на карте не отключает расчётные запреты.
3. Обход внешних препятствий в движке и отдельный проверяющий проход по полному исходному каталогу. Учтены транзит, работа, возвращение, защитные контуры самолётных сегментов и существующие проверки группового разделения/ресурсов.
4. Основное **Демо 2 — «Препятствия из KML экспертов»**. Старый синтетический пример сохранён в дополнительных примерах и тестах, старые миссии не перезаписаны.
5. ZIP доказательств выбранной миссии, отдельная CLI-проверка и тесты подмены. Применены проверки недоверенного входа из рекомендаций по безопасности; новых библиотек не добавлено.

## Как показать

1. Открыть `http://127.0.0.1:3016/planner` → **Миссии → Готовые примеры → Открыть демо 2 → Заменить текущую миссию**.
2. На карте нажать **Слои и препятствия**. В демо источник уже вложен. Для проверки импорта нажать **Загрузить KML препятствий**, выбрать `docs/planner/expert-materials/2026-09-22/originals/primorsky-obstacles.kml`, затем **Применить к миссии**.
3. **Отчёт слоя → Объекты и происхождение**: найти `UHHH103009`, нажать имя объекта. Карту приблизит к реальной вышке; источник не изменяется. Кнопка «Показать всю область» возвращает к миссии.
4. **Расчёт вариантов → Рассчитать варианты**. Оба критерия используют один вход. В этом компактном примере значения почти одинаковы — не заявляем выдуманную экономию.
5. **Проверить и подтвердить → К выполнению → Выполнить миссию**. ×1 — модельное реальное время, ×300 — ускоренный показ, не скорость БВС.
6. После завершения: **Миссии → Отчёт → Скачать доказательства ZIP**. Архив относится к выбранному сохранённому запуску, а не текущему черновику.

Обработка KML выполняется в worker. Поля отступов — изменяемые параметры модели; их изменение требует нового расчёта. Каталог хранится в IndexedDB этого браузера и origin. В другом браузере источники переносятся через JSON миссии или исходный KML.

## Высоты и полнота расчёта

Без DEM и согласования вертикальных систем нельзя сравнить absolute KML с локальной высотой миссии. Поэтому внешний контур запрещён **на всех высотах и во всё время миссии**. Реализован обход сбоку; пролёт сверху/снизу не разрешается по неподтверждённым числам. Исходные высоты доступны для будущего корректного преобразования.

Первичный отбор использует всё разрешённое воздушное пространство с запасом, а не только участок съёмки. Затем отдельный валидатор сравнивает реальные отрезки маршрута со всем каталогом, фильтруя только заведомо непересекающиеся bounding boxes. Для линий учитывается заданная физическая полуширина, не толщина нарисованного стиля. Касание буфера — конфликт. Для самолётного сегмента добавляется его манёвренный защитный радиус.

Препятствие внутри требуемой площади не вычитается молча из требования: потеря покрытия не должна становиться успешными 100%. Отказы и неопределённость не превращаются в зелёный результат.

## Формат хранения и лимиты

- Адаптер `geoscan-kml-horizontal/1`. Необязательное поле миссии `obstacleLayer` хранит исходный UTF-8 текст и политику; снимок входит в хеш миссии. Старые документы без поля сохраняют прежнее представление.
- Каталог отдельно дедуплицируется по SHA-256 исходных байтов. То же имя с другим содержимым — другая версия. Снимок внутри миссии намеренно дублирует источник: сервер и проверяющий не зависят от браузерной базы.
- Лимиты: KML 8 МиБ, 10 000 объектов, 200 000 координат, 100 000 XML-элементов, глубина 32; до 10 сохранённых версий в каталоге. Worker ограничен 15 секундами с отменой.
- Поиск локальный: до 80 релевантных объектов, прежние ограничения движка 15 км / 220 буферизованных вершин. Итоговый контроль ограничен 10 млн пар сегмент–объект. Превышение означает отказ по бюджету, **не первые N объектов и не доказанную физическую невозможность**.
- Обычная миссия по-прежнему до 200 КиБ. Запрос с вложением до 12 МиБ идёт на отдельный `/solve-with-obstacles`; `/solve` не расширен. Подробности — [API](api-v2.md).
- Один подключённый внешний источник на миссию; каталог может содержать несколько версий. KMZ, Point, MultiGeometry не поддерживаются и не пропускаются молча.

## ZIP и воспроизведение

В ZIP используется структура [BagIt 1.0, RFC 8493](https://www.rfc-editor.org/rfc/rfc8493.html): `bagit.txt`, `bag-info.txt`, два SHA-256-манифеста, содержимое в `data/`. RFC информационный; упаковка не удостоверяет автора и авиационную безопасность.

Архив включает точный вход, исходный KML, происхождение и хеш, полный отчёт импорта, расчётный контекст, кандидат, индивидуальные KML/GeoJSON, матрицу проверок и HTML. Для запуска также включены снимок операции, модельные события JSONL и управляющие события. Если запуск не выполнялся, журнал полёта не выдумывается.

```powershell
node --experimental-transform-types scripts/verify-obstacle-integration.ts
node --experimental-transform-types scripts/verify-mission-archive.ts output/obstacles-20260922/expert-mission.evidence.zip
python scripts/check-obstacle-archive-interop.py output/obstacles-20260922/expert-mission.evidence.zip
node --experimental-transform-types scripts/verify-obstacle-http.ts
```

Первый скрипт создаёт локальное контрольное выполнение и ZIP. Второй проверяет структуру/хеши, заново разбирает источник, проверяет кандидата и воспроизводит экспортированные файлы. Третий независимо читает ZIP стандартной библиотекой Python и сверяет точные байты и состав манифестов (маршруты он не проверяет). Четвёртый требует запущенный Docker-стенд на 3016 и проверяет API. ZIP-reader приложения принимает только собственный STORE-профиль и никогда не распаковывает пути на диск.

Полезные артефакты в рабочем дереве:

- `output/obstacles-20260922/verification.json`, `contingency.json`, `zip-interop.json`, `http-verification.json`.
- `output/obstacles-20260922/expert-mission.evidence.zip`.
- `output/playwright/obstacles-final/browser-mission.evidence.zip` и `archive-verification.json`: именно скачанный браузером архив завершённой миссии.
- `output/playwright/obstacles-final/`: снимки импорта, карты, завершения, консоль и журнал браузерной проверки.
- `output/obstacle-docker-final-build.log`: типы, полный набор тестов и production-сборка Docker.

## Известные ограничения и отличия от расширенного плана

1. **Нет автоматического применения нового внешнего KML к уже летящей группе.** Редактирование создаёт новую версию и отменяет её подтверждение; предыдущий запуск остаётся на своём неизменном входе. Автоматический инцидент от нового файла, проверка оставшегося пути и переключение всей группы — отдельная незакрытая часть расширенного плана. Не выдаём редактирование черновика за живое управление.
2. Нет DEM, согласования систем высот, реального автопилота и подтверждённой калибровки энергии. Сохраняются `unknown`, даже когда геометрический маршрут проходит.
3. Вместо итеративного расширения маленького пространственного отбора используется весь разрешённый коридор + запас. Независимый контроль блокирует пропуск; автоматического «расширить и пересчитать» за границы этого коридора нет.
4. Основной ZIP формируется для проверенного кандидата/запуска. Отказные результаты остаются в существующем JSON-экспорте; отдельный ZIP отказа не добавлен. Отдельный расширенный сертификат ухода сохраняется отдельным JSON, не подменяется общей матрицей.
5. Каталог индексируется bounding boxes, без R-tree/PostGIS. На полном исходнике измерен импорт около 1,1 с в Node; 3 201 объект в каталоге **не означает** допустимость 3 201 объектов в одном локальном поиске. Отдельный нагрузочный профиль памяти/мобильных браузеров не выполнен.
6. При превышении лимита HTTP локальный Wrangler иногда обрывает JSON-ответ или следующий запрос возвращает 503. Повторная проверка штатных запросов дала 200 для solve/analyze/contingency. Сам предел и запрет запроса действуют; транспортный дефект раннего отказа ещё не устранён.
7. Новые модули проходят scoped lint; глобальный lint проекта не зелёный: несвязанный вложенный конфиг другого трека и старые замечания React Compiler в workbench. Они не замаскированы отключением всего линтера.

Новые модули и тесты добавлены без новых зависимостей. `npm audit --omit=dev` на момент проверки: 0 известных уязвимостей; это не пентест и не сертификат безопасности. Исходный [PDF и его разбор](expert-materials/2026-09-22/sourcecraft-notes.md) сохранены; старый установщик не переустанавливался, удалённые репозитории/доступы не менялись.

Ограниченный поиск четырёх высокоспецифичных шаблонов ключей/приватных ключей в 92 исходниках планировщика: срабатываний нет (`credential-pattern-check.json`). Полного сканирования истории Git и всех видов секретов этим не выполнено.

**Итог:** базовые пять направлений доступны в стенде и имеют воспроизводимые доказательства. Расширенный план нельзя объявить полностью закрытым из-за перечисленных границ, прежде всего живой смены слоя. Финальную поставку, презентацию и Git push здесь не выполняли.
