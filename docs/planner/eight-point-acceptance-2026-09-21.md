## Как проверить руками за несколько минут

1. **Миссии:** загрузить `public/planner/scenarios/demo-01-survey.mission.json`, сохранить, найти по имени. Через `⋯` переименовать, архивировать, найти в «Архиве» и восстановить.
2. **Редактор:** добавить участок, нарисовать его; выбрать общий источник параметров. Изменить источник и убедиться, что параметры связанного участка обновились, а его контур не изменился. Переключить на «Индивидуальные» и изменить только этот участок.
3. **Парк БВС:** импортировать `demo-01-survey.fleet.json`, добавить нужную модель, изменить название базы, сохранить. Добавление профиля не должно превращать «Не опрошен» в реальный сигнал связи.
4. **Расчёт вариантов:** рассчитать, выбрать вариант, проверить и подтвердить. **Выполнение:** выполнить миссию, выбрать скорость, переключить сводку/БВС/журнал, изменить ширину панели.
5. **Параллельность:** пока первая миссия работает, загрузить `demo-parallel-east.mission.json`, рассчитать, подтвердить и выполнить. В «Миссиях» будут два запуска, оба продвигаются. Пауза одного не останавливает другой. Этот файл специально использует другой парк и отдельный район; совместный район не считается безопасным автоматически.
6. **Пересмотр:** на скорости ×1 сразу после запуска, пока аппарат на базе, нажать «Изменить план». Проверить сравнение/остаток, изменить параметры, пересчитать и подтвердить. Старый журнал остаётся в истории. После взлёта сначала нужна безопасная посадка; кнопка не телепортирует аппарат домой.
7. **Отчёт:** после завершения открыть отчёт из строки миссии, выгрузить JSON/HTML, проверить JSON командой ниже. Для пересмотренного запуска пакет включает проверяемую исходную историю.

## Воспроизведение проверок

```powershell
npm ci
npm run typecheck
npm run test:planner
docker compose -f compose.planner.yaml up -d --build
node --experimental-transform-types scripts/verify-missions.ts http://127.0.0.1:3016 output/eight-api
node --experimental-transform-types scripts/verify-mission-run-report.ts output/playwright/dispatcher/run.report.json
```

Для браузера нужен установленный Microsoft Edge. Каждый сценарий запускать в **новом отдельном** тестовом профиле; не очищать хранилище пользовательской вкладки.

```powershell
npx --yes --package @playwright/cli playwright-cli -s=acceptance-main open http://127.0.0.1:3016/planner --browser=msedge
npx --yes --package @playwright/cli playwright-cli -s=acceptance-main run-code --filename=scripts/verify-dispatcher-browser.js
npx --yes --package @playwright/cli playwright-cli -s=acceptance-extra open http://127.0.0.1:3016/planner --browser=msedge
npx --yes --package @playwright/cli playwright-cli -s=acceptance-extra run-code --filename=scripts/verify-eight-points-browser.js
npx --yes --package @playwright/cli playwright-cli -s=acceptance-parallel open http://127.0.0.1:3016/planner --browser=msedge
npx --yes --package @playwright/cli playwright-cli -s=acceptance-parallel run-code --filename=scripts/verify-parallel-browser.js
```

CLI может вернуть управление при диалоге до завершения сценария. Итог — свежая дата и `status: pass` в JSON-отчёте, а не сам факт завершения CLI-команды.

## Явные границы реализации

- Независимость параллельных миссий доказана консервативными **горизонтальными оболочками** маршрутов, баз и резервных площадок с запасом и разными ID аппаратов. Пересечения блокируются, а не разрешаются догадкой по высоте или часам. Это не общий 4D-диспетчер всех миссий.
- Пересмотр выполняется только на проверенной наземной контрольной точке. Исходный запуск закрывается и сохраняется, новый требует расчёта и подтверждения. Точное вычитание покрытия применяется, когда геометрия устойчива; иначе повторяется оставшаяся затронутая работа целиком с явной причиной. Заряд и срок не восстанавливаются автоматически.
- Реальный опрос БВС, отправка команд автопилоту, фоновый календарный запуск при закрытом браузере и серверный многопользовательский диспетчер не входят в готовность этого модельного стенда. Работа UI не превращает модельные состояния в телеметрию.
- Отчёт доказывает целостность модельного снимка и проверок. Реальные фотографии/бортовые логи, физическая калибровка и разрешение на полёт не заявлены. Остальные ограничения: [KNOWN-LIMITATIONS](submission/KNOWN-LIMITATIONS.md).

Коммит, push и официальная отправка комплекта жюри в этой работе не выполнялись. Реестр преимуществ обновлён: [ADV-30–33](PRESENTATION-ADVANTAGES.md).
