Рабочий стенд: **http://127.0.0.1:3016/planner**. Это инженерный MVP, не финальная сдача и не система управления реальным БВС.

## Реально проверено

- TypeScript и production-сборка проходят.
- **74 автоматических теста, 0 ошибок**: [JUnit](../../output/mission-verification/unit-tests.xml). Проверены ядро, форматы, локальное хранение, экспорт, непрерывные столкновения, 4D, батареи, освещение и регрессии.
- Scoped lint новых модулей, нового интерфейса и новых тестов проходит. Общепроектный lint не объявляется зелёным: в прежнем диагностическом интерфейсе v1 и старых тестах остаются замечания.
- В сборке npm audit сообщил 0 уязвимостей; это не полный аудит безопасности приложения.
- [API Docker](../../output/mission-docker-verification/report.json): 10 проверок, включая детерминированный повтор, повреждённый JSON, лишнее поле, размер, Origin и Content-Type.
- [Проверка доказательств из API](../../output/mission-docker-verification/independent-check.json): нет fail; unknown не удалены.
- [Работающий контейнер](../../output/mission-docker-verification/runtime.json): 2 CPU / 1 ГиБ; 21 хеш исходников внутри контейнера совпадает с зафиксированными файлами проекта. Точный image ID хранится в отчёте, не заменяется названием тега.
- [Повтор в новом контейнере](../../output/mission-docker-repeat/reproducibility.json): для 1/10/100 км² совпали входные хеши, выбранные цели, статусы, все вылеты, метрики, покрытие и проверки. Это два свежих контейнера одного образа, не два чистых сборочных окружения финального релиза.
- [Dev-браузер](../../output/playwright/mission-v2-ui-checks.md): библиотека, YAML round-trip с тем же хешем, ошибочный импорт без потери состояния, инвалидирование подтверждения, симуляция и мобильная ширина.
- [Финальный Docker-браузер](../../output/playwright/mission-v2-docker-checks.md): **24/24 проверки, 0 ошибок страницы**; импорт полигона с отверстием, реальные загрузки файлов, подтверждение и полная симуляция, desktop/mobile, центрирование модальных окон.

Время работы вычислителя и точные метрики находятся в JSON-отчётах: они зависят от нагрузки CPU. Численное покрытие округляется до 100%; не выдаётся за доказательство качества каждого реального кадра. Глобальный оптимум не доказан.

## Исправленные дефекты, закреплённые тестами

1. Вписанные дуги буфера допускали 13,858 м при требовании 15 м. Теперь используется консервативный метрический буфер с аналитической проверкой полного контура.
2. Ложные фазы, повторные ID, подделка заряда, времени и количества кадров теперь отклоняются валидатором результата.
3. Экспорт хранит направление проходов каждой работы; проверка заново строит контекст и обнаруживает подмену геометрии/ветра в представлении плана.
4. Даже менее 1% исключённой исходной территории не засчитывается как выполненная работа. Для численного шума выделен отдельный допуск 0,1 м².
5. Выбор по каждому критерию учитывает общий пул кандидатов и не оставляет заведомо худший из уже найденных вариантов.
6. Диагностический экспорт работает и при отсутствии вылетов, не рисуя выдуманный маршрут.
