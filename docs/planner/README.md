Рабочий цикл: составить задание → сравнить варианты → проверить ограничения → подтвердить версию → проиграть модель → выгрузить задания и доказательства. Это локальный инженерный стенд, **не автопилот, не телеметрия и не разрешение полёта**. Полное ТЗ ещё не закрыто; границы перечислены ниже.

## Возможности 0.3.0

- Паспорт миссии с описанием, работами, ресурсами и условиями; «Сохранить как» создаёт отдельный ID и сохраняет полный вход без прежнего подтверждения.
- Редактор флота: Custom, параметры БВС, базы, совместимость, экземпляры АКБ и группы назначений для каждой работы. Удаление аппарата очищает его батареи и ссылки. Флот JSON 1.0 импортируется с предпросмотром; коллизии ID отклоняются целиком.
- «Слои карты»: координаты GeoJSON/KML и отдельный JSON 1.0 для объёмов с высотами, временем и источниками. Ветер, облачность и видимость задаются вручную и считаются постоянными; прогноз не подключён. Высота проверяется, но не оптимизируется.
- Галерея девяти синтетических сценариев, включая автоматический выбор БВС и два примера отказа. Сравнение показывает «Раньше закончить», «Меньше летать» и доступный «Баланс» с объяснением. Баланс выбирает существующий допустимый план и может совпасть с одним из основных вариантов; налёт не выдаётся за физический износ.

Полные JSON/YAML задания загружаются обратно. MD — только читаемое описание. GeoJSON/KML плана и пакет доказательств имеют отдельное назначение; они не являются DEM или проверенными командами автопилота. Матрица девяти сценариев и форматов — в [шпаргалке](demo-guide.md). Машиночитаемые результаты нового прогона будут в `output/mission-showcase-0.3.0/`; счётчики проверок следует брать из фактических артефактов.

## Запуск

Node 24, npm; из корня проекта:

```powershell
npm ci
npm run dev:planner
```

Интерфейс: http://127.0.0.1:3015/planner. Прежний диагностический интерфейс v1: /planner/legacy. Рейтинг задач на главной странице сохранён.

Изолированный стенд:

```powershell
docker compose -f compose.planner.yaml up --build -d
```

Интерфейс: http://127.0.0.1:3016/planner. Контейнер: 2 CPU, 1 ГиБ, непривилегированный пользователь, порт только loopback, без подключения домашних папок. Образ закреплён по digest, зависимости по lockfile. Остановка без удаления: `docker compose -f compose.planner.yaml stop`.

Сборка требует сети. Расчёты локальные; подложка OpenStreetMap запрашивает тайлы у провайдера и раскрывает просматриваемую область. Для работы без запросов карт отключите подложку. Авторство OSM и Leaflet сохранено, декоративного флага нет.

## Рабочий сценарий

1. Открыть новое задание или один из девяти примеров через «Сценарии». В мастере также доступны учебные входы 1/10/100 км²; 100 км² — отдельная нагрузочная проверка. Координаты синтетической миссии не означают разрешённый участок.
2. Пройти мастер: область и работы, флот, батареи, время, ограничения и качество. Геометрию можно нарисовать или загрузить из GeoJSON/KML.
3. Рассчитать варианты по времени до последней посадки и сумме времени полётов; при наличии полного допустимого набора сравнить также рекомендацию «Баланс».
4. Прочитать проверки и допущения. Частичный, ошибочный или неподдержанный план нельзя подтвердить.
5. Подтвердить конкретную версию и запустить модельное проигрывание. Траектории и заряд берутся из тех же вылетов, что идут в экспорт. Изменение входа сбрасывает подтверждение.
6. Сохранить задание в библиотеку и дополнительно выгрузить JSON/YAML. Библиотека привязана к браузеру и адресу: порты 3015 и 3016 имеют разные хранилища. Очистка браузера удаляет локальные записи.
7. Выгрузить план группы/отдельного БВС в GeoJSON/KML и JSON-пакет доказательств. Это задания с атрибутами, не проверенные команды автопилота.

## Реализовано

- До 8 работ, 10 БВС, 100 батарей, 20 дополнительных ограничений; автоматическое или явно заданное назначение.
- JSON/YAML v2, строгая схема, понятное Markdown-описание, миграция v1, предпросмотр. Небезопасные конструкции YAML/XML отклоняются.
- GeoJSON/KML с отверстиями и несколькими частями без молчаливой потери. Библиотека IndexedDB до 50 записей: версии, конфликт замены, архив, резервная копия и атомарное восстановление.
- Дата/время, подготовка, обслуживание, повторные вылеты, экземпляры батарей и последовательная зарядка на заряднике каждого БВС.
- Маршруты мультироторов, обход постоянных запретов, проверка пространственно-временных объёмов, ожидание снятия временной зоны, непрерывная проверка взаимного сближения.
- RGB/MS/IR: камера, GSD, период и смаз. LiDAR: полоса и средняя плотность. Геофизика: шаг измерений и вынос сенсора. Это аналитические профили, не подтверждение совместимости оборудования.
- Постоянный вектор ветра: постоянная воздушная скорость либо заданная путевая скорость съёмки с проверкой необходимой воздушной.
- Положение Солнца на интервале съёмки. Порог 15° — только для выбранного режима топографической съёмки при ясном небе, не общий запрет ночных работ.
- Постпроверка сегментов, ресурса, времени, высот, зон, разделения, качества и покрытия. Допустимый остаток запланированного маршрута до назначенной посадки — консервативное свидетельство хотя бы одной достижимой посадки из каждой точки.
- Хеши входа, кандидата и подтверждения; отдельный CLI заново проверяет сохранённый пакет, не доверяя записанным pass.

## Границы версии

| Часть | Что ещё не закрыто |
| --- | --- |
| Геоскан 201 | Самолёт заблокирован до модели разворотов, катапульты и посадки; не подменяется коптером |
| Рельеф | Только unknown или явно плоская модель; нет DEM и реального AGL/AMSL |
| Энергия | Линейная по воздушному времени; нет калибровки температуры, массы, износа и мощности нагрузки |
| Качество | Нет доказанного качества реальных данных и локальной плотности LiDAR |
| Аварийный уход | Нет независимых коротких путей на альтернативные площадки и моделирования отказов |
| Высота | Проверяется заданная; пожелание ниже/выше не запускает автоматический поиск высоты |
| Масштаб | Локальный радиус 15 км, широты ±70°, лимиты геометрии; 100 км² может дать отказ или частичный план |
| Воздушная обстановка | Нет актуальных разрешений, посторонних БВС, автоматических NOTAM |
| Поиск | Эвристический и ограниченный; not_found не доказывает отсутствие любого решения |
| Независимость | Постпроверка отдельная, но использует общую геометрию с оптимизатором; это не сертификация |
| Экспорт | Исполнимость конкретным импортёром Geoscan не подтверждена |

Защитные расстояния проверяются в локальной метрической модели, не как геодезическая гарантия реального полёта. GeoJSON — 2D с отдельными высотными атрибутами; KML прижат к земле, высоты в ExtendedData. Они не выдаются за абсолютные высоты WGS84.

## Проверки

```powershell
npm run typecheck
npm run test:planner
npm run export:mission-contract
npm run verify:missions -- http://127.0.0.1:3016 output/mission-docker-verification
npm run verify:evidence -- output/mission-docker-verification/evidence-1km2.json output/mission-docker-verification/independent-check.json
```

API-прогон сохраняет фактические результаты 1/10/100 км², экспорт, хеши исходников и проверки HTTP. Успешный тест 100 км² означает корректный ограниченный ответ, **не обязательно полный маршрут**. Положительный отчёт не снимает unknown.
