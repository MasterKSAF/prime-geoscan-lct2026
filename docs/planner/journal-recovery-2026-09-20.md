# Журнал миссий: совместимость сохранённых снимков

Дата: 20.09.2026. Только модельный стенд, без команд реальным БВС.

## Причина сообщения

После обновления алгоритмов каждый сохранённый план повторно проверяется. В пакете `output/mission-showcase-0.3.0/scenarios/automatic-tradeoff/evidence-balanced.json` воспроизведены отказы `EVENT_JOURNAL` и `SAVED_CHECKS`: формулировки журнала и сохранённый состав проверок отличаются от текущего проверяющего прохода. Это само по себе не доказывает ошибку геометрии маршрута, но старое подтверждение нельзя автоматически считать актуальным.

Прежде одна неподходящая запись прерывала загрузку всего журнала через `Promise.all`. Проверки не ослаблены; исправлена обработка результатов чтения.

## Что изменено

- Записи проверяются независимо. Исправные выполнения доступны; неподходящие видны отдельно с причиной и кодами проверок.
- Исходный снимок не удаляется и не получает новое одобрение автоматически.
- Можно скачать сохранённую запись или открыть только исходное задание для нового расчёта. Старые маршруты и подтверждение не становятся исполняемыми.
- Завершённый целостный архив не мешает новым миссиям. Непроверенное активное выполнение блокирует новый запуск и продвижение симуляции: его нельзя незаметно исключить из контроля занятого пространства.
- Старую симуляцию можно явно остановить. В интерфейсе требуется отметить подтверждение: это не команда реальному БВС.
- После подтверждения запись получает архивную оболочку с полным неизменным оригиналом, его SHA-256, временем и действием `operator-confirmed-simulation-stop`. ID и место записи в хранилище сохраняются; миграции или очистки базы нет.
- Остановка не меняет заряд, координаты, посадку и готовность парка. Неготовый аппарат остаётся неготовым до отдельного подтверждения состояния оператором.
- Ошибку операции можно закрыть; закрытие уведомления не отменяет ограничения безопасности.

## Интерфейс и API

`MissionJournalReview` — компактные карточки внутри отдельного окна журнала: причина по запросу, исходный JSON, открытие задания, подтверждаемая остановка. Подписи и данные оператора выводятся текстом, а не HTML.

Хранилище/хук:

| Метод / поле | Назначение |
| --- | --- |
| `inspect()` / `rejected` | Исправные выполнения и отдельные отклонённые записи |
| `exportRaw(id)` | Полная сохранённая запись, включая архивную оболочку |
| `recoverDocument(id)` | Проверенная структура исходного задания без запуска старого плана |
| `archiveRejected(id, originalHash)` | Явная остановка старой симуляции с проверкой ожидаемого снимка |
| `dismissError()` | Закрытие ошибки действия без изменения данных |

Совместимость: прежний `list()` остаётся строгим для программных потребителей, которым нужен целиком проверенный журнал. UI использует `inspect()`.

## Риски и ограничения

1. Нарушенную целостность нельзя обойти кнопкой архивирования: доступна выгрузка для проверки, автоматическое освобождение симулятора запрещено.
2. Хеши проверяют согласованность локальных данных, но не являются электронной подписью, подтверждением телеметрии или разрешением на полёт.
3. Параллельные изменения другой вкладкой проверяются атомарно. При конфликте действие не применяется, нужен новый просмотр истории.
4. Лимит журнала остаётся 20 записей; автоматического удаления архивов нет. Предельный размер архивной оболочки также ограничен 5 МиБ.
5. Неподдерживаемая старая схема задания может не открыться для пересчёта; исходная запись всё равно сохраняется. Целостный снимок прежней версии движка нельзя возобновлять, но его можно явно остановить и сохранить.
6. Неизвестные проверки полётной модели не становятся положительными из-за исправления журнала.

## Проверки

Отдельные целевые прогоны завершились успешно:

- 31 тест хранилища, координатора команд и восстановления, включая 8 новых регрессионных тестов.
- 37 связанных тестов батарей, межмиссионной безопасности, нештатных ситуаций и продолжения оставшихся работ.
- 8 тестов жизненного цикла карты. Harness использует настоящий `mission-vehicle-label.ts`, а не заглушку; проверяет сохранение маркера и смену силуэта коптера на самолёт.

Проверены: изоляция старого завершённого снимка; блокировка старого активного; явная остановка; сохранение оригинала и состояния парка; повреждённые хеши; повреждённая архивная оболочка; противоречивый завершённый статус; предыдущая версия движка; запрет обхода обычной отмены для исправного выполнения; закрытие ошибок без удаления причин из истории.

Команды повторения:

```powershell
node --experimental-transform-types --test tests/mission-operations.test.ts tests/mission-operations-hook.test.ts tests/mission-operations-recovery.test.ts
node --experimental-transform-types --test tests/mission-cross-operation-safety.test.ts tests/mission-current-battery.test.ts tests/mission-safety.test.ts tests/mission-remaining-work.test.ts
node --experimental-transform-types --test tests/mission-map-lifecycle.test.ts
npm run test:planner
```

Браузерная проверка интегрированного окна и общий релизный прогон фиксируются отдельно в итоговом отчёте; перечисленные модульные тесты их не заменяют.
