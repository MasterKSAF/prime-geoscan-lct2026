# Рабочее обновление 0.3.5 · 23 сентября 2026

Проверено на Docker-стенде `http://127.0.0.1:3016/planner`, контейнер healthy, ядро 0.3.5. Решение не заморожено. Commit/push, публикация и видеодемонстрация с озвучкой не выполнялись.

## Изменения

1. Общий модельный реестр из 12 БВС: все три модели активны. В региональном входе Демо 1 и 3 — одинаковые 8 аппаратов с общими ID; в Демо 2 — 4. Базы не перемещаются автоматически между районами. Автовыбор учитывает установленную камеру, профиль, ограничения и резерв батареи.
2. Добавлены два Gemini с Pollux в северном районе. Демо 1 после добавления MS рассчитывает всю RGB- и MS-работу, а не выдаёт частичный маршрут за выполненную миссию.
3. Парк управляется по конкретному аппарату: доступность и комплектация, ID, район и заряд. Занятые БВС защищены от изменения; новый расчёт не обнуляет расход батареи.
4. Непройденные проверки сразу развёрнуты и выделены, причина не заменяется абстрактной «неподдержанной конфигурацией». Подсказки ведут к доступности парка или назначению работ. Сначала предлагается задействовать подходящие существующие аппараты; предложения проверяются новым расчётом.
5. Анализ сокращён до отказов, общего списка проверок и подходящих вариантов исправления. Остальные диагностические данные не удалены из доказательств.
6. В отчёте отдельный столбец «Проверки плана», результат и «Все проверки». Выбор строки не подменяется миссией, открытой в редакторе. Последний расчёт сохраняется при изменении черновика; старое разрешение запуска не действует.
7. «Настройки → Начать с нуля»: подтверждаемый сброс текущей браузерной сессии, остановка симуляций, очистка расчётов/журналов/видео/правок, восстановление трёх карточек и активного парка. Отмена сохраняет состояние. Код и скачанные материалы не удаляются; Docker не перезапускается.
8. Уведомление не блокирует клики по элементам под текстом; собственные кнопки уведомления остаются кликабельными.

## Важные границы

- Все модели доступны для подбора, но не обязаны участвовать в каждом плане. У каждого аппарата только установленное оборудование, а не все камеры модели одновременно.
- Демо 3 сохраняет явное назначение БВС с 26% для отрицательного примера. Автовыбор из здорового парка — проверяемое исправление; заряд сам собой не растёт.
- Применение исправления с заменой батареи/оборудования — явное подтверждённое изменение **модели**, а не реальная телеметрия или команда аппаратуре. Неизменённые ресурсы сохраняют состояние.
- Занятость других миссий и безопасные интервалы продолжают проверяться. Поиск ограничен CPU-бюджетом; глобальный оптимум и реальные полёты не заявляются.
- История в этой версии — последний расчёт и один запуск на каждую из трёх миссий в текущей сессии. Для хранения вне сессии нужны выгрузки.

```powershell
npm run typecheck

npx --yes --package @playwright/cli@0.1.20 playwright-cli -s=fleet35 run-code --filename scripts/checks/release35-reset-browser.js
npx --yes --package @playwright/cli@0.1.20 playwright-cli -s=fleet35 run-code --filename scripts/checks/release35-completed-browser.js
node --experimental-transform-types scripts/verify-mission-archive.ts output/playwright/0.3.5-demo2-evidence.zip
npx --yes --package @playwright/cli@0.1.20 playwright-cli -s=fleet35 close
```

Браузерные сценарии выполняются последовательно в отдельном тестовом профиле и сами подтверждают сброс только своей сессии. Проверяют RGB + MS, разные критерии, сохранение отчёта, правильную привязку проверок, Демо 2/3, отмену сброса, сброс работающей симуляции и фактическое применение рекомендаций.
