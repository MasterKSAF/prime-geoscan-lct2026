# Комплект ПРАЙМ · Planner 0.4.0

25 сентября 2026 года. Переносимая локальная поставка, не официальный акт приёмки, не отправка формы и не заморозка Git.

## Состав

| Каталог | Назначение |
| --- | --- |
| `source/` | Код, зависимости, Docker, тесты, документация и исходные слои |
| `docs/` | Паспорт PDF и указатель документов |
| `presentation/` | Одна актуальная пара PDF/PPTX |
| `video/` | Одобренная демонстрация с озвучкой, 8:12 |
| `evidence/demo-1/` | Завершённый Демо 1 и независимая проверка ZIP |
| `evidence/ui/`, `evidence/downloads/` | Браузерные шаги, скриншоты, Демо 2/3 и выгрузки |
| `evidence/engine/` | Сводный протокол, тесты и сборка |

В корне: `README.md`, `MANIFEST.json`, `MANIFEST.sha256`, `SHA256SUMS`. Рядом с каталогом — одноимённый ZIP и `.zip.sha256`. Контрольные суммы не являются электронной подписью.

## Проверка и запуск

1. Распаковать ZIP. До изменения файлов проверить целостность из корня распакованного комплекта:

```powershell
node source/scripts/build-submission-package.mjs --verify .
```

2. Перейти в `source/` и запустить Docker по README. Нужен интернет для первой установки зависимостей и картографической подложки.
3. Пройти [три сценария](DEMO-SCRIPT.md), скачать файлы и повторить проверку ZIP по [инструкции](EXPERT-FILES.md).

У исходников сохраняется структура. Единственное преобразование страницы общего рабочего каталога: `app/page.tsx` в поставке перенаправляет на `/planner`; преобразование и хеши записаны в манифесте. Другие треки, `.git`, `node_modules`, секреты, браузерные сессии и записи встреч не включаются.

Автономная сборка проверяет переносимость, но **не заменяет чистый клон финального коммита**. Исходный код Planner 0.4.0 хранится в закрытом GitHub; перед сдачей каждому назначенному эксперту предоставляется и проверяется гостевой доступ. Публичный доступ не включаем. Точный проверенный образ и результаты — в [протоколе](VERIFICATION.md); последующие проверки клона фиксируются отдельно.

## Пересборка для разработчика

`scripts/build-submission-package.mjs --source-only` создаёт отдельную копию. Собрать её Docker и сохранить протокол. Затем `PLANNER_VERIFIED_SOURCE` указывает на родительский каталог проверенной копии (с `SOURCE-CANDIDATE.json`). Запуск сборщика без аргументов сравнивает ядро с копией, собирает материалы и проверяет ZIP. Отсутствующие обязательные файлы или несовпадающие хеши не должны давать успешный комплект.

Скрипт не публикует материалы, не меняет приватность и не выполняет Git. [Порядок сдачи](SUBMIT.md), [внешние действия](READINESS.md).
