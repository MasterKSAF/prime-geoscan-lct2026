## Один комплект, один вход

Распакуйте `PRIME-Planner-0.4.0.zip` и начните с `README.md`. Оригинальная структура кода и его документации сохранена в `source/`. Рядом лежат удобные для просмотра материалы:

| Каталог | Что открыть |
| --- | --- |
| `source/` | Код, тесты, Docker, README запуска; `source/docs/planner/submission/` — подробные инструкции |
| `docs/` | Указатель, паспорт PDF и порядок сдачи |
| `presentation/` | Одна актуальная презентация PDF и редактируемый PPTX |
| `video/` | `Planner-Demo1-PRIME-soft-voice.mp4`, обзор и полный модельный полёт ×10 за 8:12 |
| `evidence/` | Входы, планы, индивидуальные маршруты KML/GeoJSON, проверки и журналы демонстрационных сценариев |
| `MANIFEST.json`, `SHA256SUMS` | Состав и контрольные суммы файлов. Это контроль целостности, не электронная подпись |

Исходные слои экспертов и параметры камер не удаляются. Погодные условия, телеметрия и материалы съёмки в демо модельные. Исторические исследования, если нужны по ссылкам, находятся отдельно от свежих приёмочных доказательств.

## Самостоятельная проверка за несколько шагов

1. Запустите Docker по `source/README.md`, откройте `/planner` на порту 3016.
2. Демо 1: расчёт двух критериев, подтверждение, выполнение, отчёт, ZIP.
3. Демо 2: несколько работ, препятствия и разнесение аппаратов; проверьте также изменение базы/границы на копии.
4. Демо 3: ожидаемый отказ, объяснение причины и новый расчёт после исправления. Отказ нельзя выдавать за завершённый полёт.
5. В `evidence/` откройте итоговый протокол; каждый ZIP можно независимо проверить командой из [инструкции по файлам](EXPERT-FILES.md).

## Размещение материалов

1. **GitHub:** исходный код Planner 0.4.0 хранится в закрытом репозитории. Публичный доступ не включаем. До сдачи получить GitHub-логины назначенных экспертов, предоставить каждому гостевой доступ для проверки и проверить, что приглашение принято и репозиторий можно просмотреть и клонировать под его учётной записью. Перед приглашением проверить доступные роли и выбрать минимальные согласованные права. Одной ссылки на закрытый репозиторий недостаточно. Зафиксировать commit сданного среза; проверка исходников из чистого клона не заменяется наличием ZIP. Не добавлять кэши, секреты, посторонние проекты и старые видео.
2. **Google Drive:** загрузить полный ZIP, презентацию PDF и итоговое видео. Открыть просмотр по ссылке. Большие медиа не обязательно хранить в истории Git.
3. **Прототип:** по решению команды указываем прямую ссылку Google Drive на финальное видео. Отдельный сайт не разворачиваем. Локальный стенд воспроизводится из исходников. Переданная инструкция допускает демонстрацию для алгоритмического/бэкендового решения; окончательное принятие формы определяют организаторы.
4. **Личный кабинет организаторов:** сохранить ссылки в пяти полях ниже. Прямой адрес кабинета и факт подачи этим документом не подтверждаются.
