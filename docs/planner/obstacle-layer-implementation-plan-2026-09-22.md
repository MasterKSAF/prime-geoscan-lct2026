# План доработки: препятствия экспертов, маршрутизация и доказательства

Дата: 22.09.2026. Статус: **план реализации, не отчёт о выполнении**.

Трек: **«Сервис планирования и распределения беспилотных авиационных работ» — Геоскан, задача № 5.**

## 1. Результат и границы работ

Оператор загружает исходный KML экспертов, видит препятствия на карте и рассчитывает миссию. Система учитывает их при съёмке, перелётах, маневрировании и возвращении; проверяет согласованность полётов группы и ресурс каждого аппарата. Если проверенного маршрута нет, запуск не предлагается. Из отчёта миссии скачивается архив с входными данными и воспроизводимыми проверками.

Сейчас делаем пять направлений: **импорт → каталог и карта → расчёт с ограничениями → демонстрация → доказательства**. Безопасность загрузки и регрессии входят в каждое направление.

В эту итерацию **не входят** финальная сборка комплекта для сдачи, обновление презентации, публикация репозитория, выдача доступа экспертам, 3D и подключение реального автопилота. Точечные изменения интерфейса для новых функций входят; окончательный редизайн не является условием начала работ.

ZIP отдельной миссии — функция стенда, а не финальный архив всего проекта. Результаты остаются модельными, не подтверждают реальный полёт и не гарантируют 100 баллов или первое место.

- **2 777 объектов имеют `absolute`, 424 — `relativeToGround`.** Нет DEM, подтверждённой точности, даты обследования каждого объекта и согласования с локальными высотами миссии.
- Установщик Planner по второй ссылке — не отдельная миссия и не подтверждённый набор рельефа. Старую версию не устанавливаем поверх новой ради этой доработки.

Нельзя решить задачу одним увеличением лимита загрузки или преобразованием всех объектов в плоские полигоны с потерей исходных высот.

## 4. Направление 1 — надёжная загрузка слоя

### 4.1. Отдельный контракт

Ввести `ObstacleLayer` с собственной версией, не расширять бесконтрольно обычный JSON миссии. Хранить:

- исходные байты, исходное имя, источник и SHA-256;
- ID слоя и версию адаптера;
- стабильный ID объекта: хеш источника + исходный XML ID, либо документированная позиция при отсутствии ID;
- имя, исходный тип геометрии, все координаты и высоты;
- исходные `altitudeMode` и `extrude`, отдельно нормализованную расчётную интерпретацию;
- статус геометрии, преобразования, предупреждения и границы применимости;
- профиль буферов и его происхождение, отдельно от фактов исходного файла.

Имя объекта не является уникальным ID. Неизвестное назначение объекта не является основанием его отбросить. Повторная загрузка одинаковых байтов не создаёт дубликаты; файл с тем же именем и другими байтами создаёт новую версию.

### 4.2. Разбор и ошибки

1. Проверить размер и формат до полноценного разбора.
2. Разобрать Polygon и LineString из предоставленного файла; сохранить высоты каждой вершины. Иные геометрии явно перечислять как неподдержанные, а не пропускать.
3. Проверить конечность чисел, диапазоны координат, порядок осей, число вершин, вырожденность и топологию. Отверстия не заполнять молча.
4. Замыкать незамкнутые кольца только в производной геометрии; записывать объект, действие и результат проверки. Самопересечение не «лечить» выпуклой оболочкой без явного решения.
5. Формировать отчёт: всего, пригодно к расчёту, нормализовано, проблемно; исправленные входят в принятое, поэтому категории не должны ошибочно суммироваться дважды.
6. Сохранять исходник неизменным. При отмене или ошибке прежний рабочий слой остаётся действующим.

Все 3 201 объекта должны получить запись в отчёте. **Это не обещание признать всю геометрию пригодной до топологической проверки.** Непригодный потенциально релевантный объект блокирует утверждение плана; его нельзя скрыть и получить зелёную проверку. Если положение ошибочного объекта определить нельзя, блокируется расчёт со всем таким слоем до исправления источника.

### 4.3. Ограничение ресурсов

Начальные инженерные бюджеты для измерений: 8 МиБ на KML, 10 000 объектов, 200 000 координат, отдельные лимиты глубины XML, элементов, длины полей и времени обработки. Это наши лимиты, не числа из ТЗ; фиксируем их окончательно после замеров на ноутбуке.

Разбор/индексация не должны замораживать главный поток браузера: worker, прогресс и отмена. Пределы клиента и сервера согласованы; при превышении — понятный отказ, никогда не первые N объектов с сообщением об успехе. KMZ и произвольные ZIP на входе в первом выпуске не нужны: официальный пример — KML.

**Приёмка:** исходный файл загружается без подготовки; каждый объект учтён; исходные байты и высоты сохранены; повреждённый файл не заменяет старый слой; отмена работает.

## 5. Направление 2 — каталог, карта и версии

### 5.1. Отдельный слой, общий для нескольких миссий

- Каталог хранится отдельно от участков съёмки, парка и ручных запретов. Использовать текущую инфраструктуру IndexedDB, проверять доступное место и атомарность записи.
- Миссия привязывается к определённой версии слоя и профилю безопасности. Новый файл не переписывает завершённые/выполняемые операции.
- Полный источник доступен проверяющему. Клиентский ID из IndexedDB сам по себе недостаточен серверу: API должен получить и проверить соответствующие данные.
- Предпочтительный первый вариант API: отдельный версионированный запрос «миссия + источники слоёв + политика», с отдельным ограничением размера и повторной валидацией на сервере. Старый `/missions/solve` для миссий без внешнего слоя сохраняется.
- Расчётный контекст связывается хешем с миссией, исходниками, адаптером, буферами и выбранной системой высот. План, подтверждение, операция и экспорт ссылаются на один контекст.
- Отсутствие файла по ссылке/хешу — ошибка «не хватает слоя», а не разрешение решить без препятствий.

Не превращаем 3 201 объект в 3 201 элемент редактируемой формы с лимитом 20. Внутренние функции получают отдельный проверенный каталог ограничений; существующий предел ручных объёмов не ограничивает внешнюю проверку.

### 5.2. Минимальный интерфейс

В редакторе рядом с картой: **«Слои → Препятствия → Загрузить KML»**. После импорта — одна компактная строка с именем, количеством объектов, состоянием и меню. Отчёт и правила обхода открываются по запросу; объяснения — через `i`.

- Объект на карте: имя/ID, тип, исходная высота и её смысл, применённый буфер, источник.
- Разные, ненавязчивые обозначения исходного контура и защитного отступа.
- Поиск по имени/ID и переход к объекту; линии тоже кликабельны.
- «Показать/скрыть» меняет только карту. **Скрытый слой продолжает участвовать в расчёте.** Отключение в расчёте — отдельное явное изменение миссии с аннулированием старого результата.
- Удаление связи со слоем не удаляет его из исторического отчёта. Изменение буфера не переписывает исходник.
- Не переносить карту на весь Приморский край при каждом пересчёте; сохранять текущий масштаб, «Показать слой целиком» — отдельная команда.
- Короткие закрываемые уведомления поверх правого верхнего угла, без сдвига карты и повторных полос на всю ширину.

Отрисовку можно упрощать/ограничивать текущим окном карты. Расчёт и проверка используют полную исходную нормализованную геометрию, не экранные упрощения.

**Приёмка:** перезагрузка сохраняет слой; скрытие не меняет маршрут; переключение миссий не путает версии; удаление/замена не портят историю; карта не исчезает.

## 6. Направление 3 — автоматический учёт и независимая проверка

### 6.1. Высоты: первый выпуск без ложного пролёта сверху

`absolute` и `relativeToGround` имеют разные основы отсчёта; наше `mission-reference` — третья, локальная модель. Их нельзя сравнивать как одно число. [Официальное описание KML](https://developers.google.com/kml/documentation/altitudemode).

Первый выпуск: для объектов с несогласованными высотами строим **запрет пересечения их горизонтального контура на любой расчётной высоте**, с защитным буфером. Для линий — коридор вдоль всей линии. Это явная консервативная модель обхода сбоку; нельзя разрешить «пройти ниже», потому что абсолютная отметка случайно больше высоты маршрута.

Ширина линии KML — оформление, не физическая ширина препятствия. Полуширину и запас задаём отдельными параметрами с источником/допущением. В отступе различаем размер аппарата/манёвра, оценку ошибки координат и дополнительный запас. Не объявляем произвольное значение нормативом; неизвестная точность остаётся явно неизвестной.

Пролёт сверху оставляем отдельным последующим режимом: только при совместимых высотах маршрута, земли и препятствия, проверенном преобразовании и известной погрешности. Не нужен, чтобы реализовать горизонтальный обход сейчас. Обход препятствий **не доказывает отсутствие столкновения с рельефом** и не превращает учебное воздушное пространство в реальное разрешение на полёт.

### 6.2. Где искать препятствия

Начальная область отбора включает все работы, базы, посадки/резервы, транзитные коридоры, манёвры и запас поиска обхода. Пространственный индекс ускоряет отбор, но не задаёт область доказанной безопасности.

1. Построить кандидата с учётом полного набора релевантных объектов, ручных запретов и разрешённого пространства.
2. Проверить весь полученный путь независимым проходом по каталогу. Для первого реального набора допустим полный перебор 3 201 ограничивающего прямоугольника с точной геометрией потенциальных пересечений.
3. Если обход вышел за исходную область отбора и встретил новый объект, расширить контекст и пересчитать.
4. Ограничить число расширений и время поиска. Исчерпанный бюджет означает «проверенное решение не найдено», не доказанную физическую невозможность.
5. Независимый валидатор не доверяет переданному планировщиком списку «учтённых препятствий»: он выводит набор из полного сохранённого слоя.

Обязательны препятствия **за пределами участка съёмки**, если они находятся по дороге от/к базе. Аналогично для защитного возврата: прямая линия до ближайшей базы не является достаточным доказательством достижимости.

### 6.3. Маршрутизация и общие ограничения

Расширить существующую маршрутизацию, а не прокладывать декоративную линию поверх старого расчёта. Проверять все фазы: взлёт/набор, транзит, проходы съёмки, переходы между проходами, развороты/ожидание, снижение, посадка, защитный возврат.

- Для коптеров — обход буферизованных контуров с проверкой каждого отрезка и манёвра.
- Для самолётного профиля 201 — его существующие ограничения и защитные объёмы; путь, доступный коптеру, не считать автоматически допустимым для самолёта.
- Запреты по высоте/времени из миссии продолжают действовать. Внешние препятствия не заменяют ограничения воздушного пространства.
- После каждого обхода пересчитывать расстояние, время, налёт, расписание, батарею и достижимость посадки. Сохраняется правило: повторные вылеты на текущем остатке; неизвестную будущую замену АКБ не придумываем.
- Перепроверять разделение всех БВС и пересечения с другими выполняемыми миссиями, включая изменившиеся моменты старта/возвращения. Нельзя ограничиться проверкой отдельных статичных путей.
- Не удалять неудобные части области из требуемого покрытия. Если препятствие делает часть работы недоступной, показывать недовыполнение/отказ. Изменить заказанную площадь можно только явно новой версией миссии.
- Рекомендации при отказе проверять отдельным расчётом. «Заменить батарею» не исправляет закрытый коридор; «добавить БВС» не отменяет запретную зону.

### 6.4. Что означает «проверено»

Проверка пересечений непрерывных сегментов/защитных объёмов во времени, а не только кадров анимации. Касание защитной границы — конфликт с учётом согласованного численного допуска. Порог построителя не может быть слабее порога проверяющего.

Для каждого конфликта: БВС, вылет, фаза, отрезок, объект, координата/интервал времени и нарушенное правило. Для каждого успешного результата — область проверки, набор объектов, политика, минимальный запас там, где он действительно рассчитан. Если оценка приближённая, указываем метод и границы, а не выдаём её за точное расстояние.

Новые данные во время модельного выполнения создают новую версию и инициируют проверку оставшегося пути. Старый запуск не переписывается. При угрозе или неполной проверке нельзя продолжать обычную анимацию с зелёным статусом; показываем инцидент и только проверенные варианты защитного действия. Не обещаем онлайн-перепланирование реального автопилота.

**Приёмка:** маршрут обходит релевантные препятствия во всех фазах; независимая проверка ловит намеренно испорченный план; ресурс и разделение пересчитываются; отсутствующие данные/тайм-аут не превращаются в успех.

## 7. Направление 4 — три понятных демонстрации

Не увеличиваем число основных демонстраций. **Заменяем Демо 2 в основном показе**, а прежний синтетический вариант сохраняем под отдельным ID как регрессионный тест. Существующие сохранённые миссии не перезаписываем по старому ID.

| Сценарий | Что показывает | Результат |
| --- | --- | --- |
| 1. Обычная съёмка | Создание/загрузка, парк, автоматическое распределение, два критерия, выполнение и отчёт | Понятный успешный полный цикл |
| 2. Препятствия из файла экспертов | Импорт исходного KML, реальный локальный фрагмент, обход и согласование двух БВС | Полное покрытие, проверенные пути и журнал влияния препятствий |
| 3. Выполнить нельзя — как исправить | Не хватает ресурса либо закрыт допустимый путь; проверка предложенного изменения | Понятный отказ и проверенная рекомендация либо честное отсутствие решения |

### Постановка нового Демо 2

1. Подобрать небольшой участок в границах исходного слоя — ориентир несколько сотен метров / 1–2 км, окончательные координаты выбрать после геометрических проверок. Не рисовать препятствия, выдавая их за исходные.
2. Два БВС, например RGB и MS, с явными профилями; базы, область съёмки, время и допустимый воздушный коридор заданы нами как демонстрационные условия. Не приписывать их экспертам.
3. Выбрать постановку, в которой прямой транзит пересекает реальное препятствие вне области работ, а допустимый обход существует. Желательно присутствие и полигона, и линии; если поблизости нет обоих, линию показать отдельным регрессионным примером, не переносить исходные координаты.
4. В интерфейсе: «Загрузить слой» → краткая сводка → «Рассчитать варианты» → маршрут и проверка → модельное выполнение → «Скачать доказательства».
5. Исходную опасную прямую показывать только как диагностическое сравнение, не запускаемый вариант. Не считать её допустимым baseline для процентов экономии.
6. Оба оптимизационных варианта используют одинаковые препятствия. Показывать фактическую разницу времени/налёта, без обещания, что они всегда различаются.
7. Отдельной проверкой намеренно совместить конфликтующие полёты: валидатор должен отказать. Не заставлять настоящую демонстрацию сначала столкнуть БВС.

Вариант Демо 3 с препятствиями можно открыть из дополнительных примеров: безопасный коридор полностью закрыт. Никакая смена батареи не должна давать ложный успех. Система может проверить другую **заданную допустимую** базу/работу/окно, но не предложить игнорировать препятствие.

Ветер и время в основном показе фиксируются во входе ради воспроизводимости. Получение актуального прогноза показывается отдельно; его сбой не ломает демонстрацию.

## 8. Направление 5 — доказательства отдельной миссии

### 8.1. Формат

Предлагается ZIP с **BagIt 1.0, RFC 8493**, SHA-256-манифестом файлов и собственным версионированным содержимым миссии. BagIt описывает упаковку/целостность, а не авиационную безопасность; RFC имеет информационный статус. Это наш выбор, не предписание организатора. [Первичный источник](https://www.rfc-editor.org/rfc/rfc8493.html).

В корне: `bagit.txt`, `bag-info.txt`, `manifest-sha256.txt`, `tagmanifest-sha256.txt`. Полезные файлы находятся в `data/`; контрольные суммы считаются по точным байтам. Соответствие формату проверяем тестами и независимым совместимым проверяющим инструментом перед заявлением поддержки.

Содержимое, определяемое нашим проектом:

| Путь внутри `data/` | Содержимое |
| --- | --- |
| `README.md` | Как открыть отчёт и повторить проверки, версии контракта |
| `input/mission.json` | Точная версия миссии, парка, батарей, работ, времени и условий |
| `sources/obstacles.kml` | Неизменный исходный слой, при нескольких слоях — отдельные файлы по безопасным ID |
| `sources/provenance.json` | Источники, хеши, время получения, состояние неизвестных данных |
| `obstacles/import-report.json` | Все объекты и результаты разбора, исправления/отказы |
| `obstacles/context.json` | Политика высот, отступы, область отбора, релевантные ID, версии обработки |
| `plan/candidate.json` | Выбранный план, расписание и метрики |
| `routes/<vehicle-id>.kml` и `.geojson` | Отдельный маршрут каждого БВС со временем, высотой, скоростью и фазами |
| `checks/validation.json` | Независимые геометрические, временные, ресурсные и групповые проверки |
| `checks/requirements.json` | Требование → проверка → результат → ссылка на доказательство |
| `run/events.jsonl` | Журнал конкретного модельного запуска, не реальные бортовые измерения |
| `run/report.json` | Проверяемый снимок запуска и история пересмотров |
| `report.html` | Краткий понятный человеку отчёт, открываемый локально |
| `reproduce.json` | Версия движка, входа и адаптера, параметры, бюджет поиска, окружение |

Для незапущенного расчёта журнал выполнения не фабрикуется: архив отмечается как расчётный. Для прерванной миссии отчёт не показывает завершение. Доказательства берутся из сохранённой версии выбранного запуска, а не из последнего состояния редактора.

### 8.2. Повторная проверка

Расширить текущие `missionEvidence`, `missionRunReport` и CLI-проверку, сохранив поддержку прежних отчётов. Для нового формата проверяющий должен:

1. Проверить структуру и каждый хеш, включая наличие всех заявленных источников.
2. Повторно разобрать исходный KML и проверить соответствие производного каталога.
3. Независимо проверить сохранённый маршрут на полном релевантном наборе объектов, расписание, батареи, покрытие и разнесение.
4. Сопоставить KML/GeoJSON с тем же планом; высоты в локальной системе не подменять фиктивными AMSL-координатами.
5. Выдать машинный отчёт и ненулевой код завершения при проблеме.

Хеши защищают от незаметной порчи при сравнении с известным манифестом, но не удостоверяют автора и не мешают злоумышленнику пересчитать весь изменённый пакет. Корректность устанавливает повторная проверка, не сам SHA-256.

Текущую функцию `canonicalStringify` не объявлять реализацией RFC 8785 без отдельного соответствия. Для упаковки достаточно хешей точных байтов. Повторная проверка сохранённого кандидата обязательна; совпадение нового результата ограниченного по времени поиска на другом CPU не обещаем. Для стабильных тестов — фиксированный порядок/бюджет итераций, версия и seed, если применяется случайность.

Кнопка **«Скачать доказательства ZIP»** располагается в отчёте выбранной миссии. По возможности рядом — «Проверить архив», с теми же ограничениями недоверенного ввода; CLI остаётся обязательным воспроизводимым способом. Загрузка произвольного ZIP для планирования в эту итерацию не входит.

## 9. Безопасность и остальные материалы

Применяем полезное из PDF, не называя это новым набором требований Геоскана:

- KML/JSON считаются недоверенными: ограничение размера/сложности, строгие числа и типы, запрет DTD/внешних сущностей и сетевого разрешения ссылок.
- `NetworkLink`, внешние иконки/модели и стили не запускают загрузку ресурсов. Текст названий/описаний не исполняется как HTML в карте или отчёте.
- Имена из файла не используются как пути. У архива — контролируемые имена; у проверяющего — запрет выхода из директории, абсолютных путей, дубликатов и чрезмерной распаковки.
- Сохраняется защита API по источнику запроса, типу тела, лимитам и параллельным расчётам. Это локальный стенд, не обещание готовой многопользовательской системы с авторизацией.
- Проверяем зависимости, секреты, сборку, типы и тесты. Замечания разбираются; «сканер запущен» не равно «безопасно». Известные диагностики React Compiler не скрываются и не попадают в зелёный итог без решения/отдельного объяснения.
- Новые библиотеки добавляются только при необходимости, с фиксированной версией и проверкой лицензии; поиск маршрута не выносится в платный/облачный сервис.

Практические ориентиры: [OWASP — загрузка файлов](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html), [OWASP — защита от XXE](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html). Соответствие отдельному сертификационному стандарту не заявляется.

Исходный PDF и его MD-разбор остаются в документации. В каждую миссию 59-страничный доклад не вкладываем — это не вход маршрутизации. В дальнейшем перед сдачей проверить выданный команде SourceCraft и доступ экспертов. Сейчас не менять удалённые репозитории, права и квоты.

## 11. Порядок реализации и точки остановки

Планировать по законченным приращениям; следующий этап не закрывает ошибки предыдущего красивым интерфейсом.

| Этап | Работы | Контрольная точка |
| --- | --- | --- |
| A | Зафиксировать исходный файл и тестовые фрагменты; описать контракт и политику неизвестных высот | Схема и ожидаемые отказы согласованы; прежние миссии читаются |
| B | Адаптер, отчёт, безопасное хранение и карта | Полный исходник импортирован, все объекты учтены, UI не зависает |
| C | Расчётный контекст, API, пространственный отбор и обход | Реальный локальный фрагмент обходится; слой связан с хешем результата |
| D | Независимый контроль, возврат, разделение, батареи и покрытие | OBS-04…OBS-14 проходят, намеренно плохие планы отвергаются |
| E | Новое Демо 2, отчёт и ZIP, CLI-проверка | Полный пользовательский цикл и проверка распакованного архива |
| F | Полные регрессии, безопасность, CPU-замеры, Docker и браузер | Матрица OBS-01…20 с фактическими результатами и остаточными ограничениями |

Ориентир для планирования: **4–6 полноценных рабочих дней плюс резерв на геометрию/производительность**. Это оценка объёма, не гарантированный срок. Уточнить после B/C. Если времени мало, сокращаем дополнительную визуализацию, не полноту слоя, проверки и отчёт об отказах.

После каждого этапа — короткий отчёт: что работает, какими проверками подтверждено, что ещё не реализовано. Не запускать длинный полный набор после каждой правки; сначала узкие тесты, затем полные проверки на контрольных точках.

## 13. Основные риски и решения

| Риск | Решение |
| --- | --- |
| Несогласованные высоты/нет рельефа | Горизонтальный обход всех высот, явные ограничения; не обещать реальную безопасность над рельефом |
| Неизвестная ширина/точность препятствия | Отдельный документированный профиль отступов; неопределённость не маскировать нормативом |
| Плохая геометрия | Проверка топологии, журнал преобразований; релевантные ошибки блокируют подтверждение |

| Взрыв сложности поиска/зависание | Ограниченные задачи, worker, индексация, измерения; отказ по бюджету без усечения безопасности |
| Обход ухудшает батарею/сближение/покрытие | Полный повторный расчёт взаимосвязанных проверок |
| Слой обновился после подтверждения | Версионирование и неизменные снимки; новый контекст требует новой проверки |
| Архив выглядит убедительно, но неполон | Матрица требований, повторный разбор исходника, проверка изменённых архивов |
| Несовместимость старых миссий/отчётов | Версионированный новый контекст, регрессии чтения старых форматов |
| Слишком много текста в UI | Сводка и действия на первом уровне; подробности в карточке/отчёте и `i` |

## 14. Определение готовности этой итерации
