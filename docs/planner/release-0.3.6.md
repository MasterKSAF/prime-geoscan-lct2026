# 0.3.6 — групповой возврат и диагностика событий

Рабочее обновление; решение не заморожено. Коммит и публикация не выполнялись.

## Изменения

- Возврат проверяется для группы с индивидуальными ожиданиями 0/15/30/60/120 секунд и несколькими допустимыми высотами. Дополнительные ожидания и набор высоты расходуют батарею. Они не отменяют предельный ветер, потолок, временное окно, ограничения и защитные расстояния.
- Мультиротор на взлёте может сначала вертикально подняться в текущей позиции, затем лететь к площадке. Проверяется вся траектория, включая этот подъём. Самолёту не назначается зависание; используется прежний профиль самолётного возврата.
- Диспетчер перебирает совместимые комбинации маршрутов; возвращается к предыдущему выбору, если он блокирует другой аппарат. Предел — 2000 узлов поиска, не доказательство глобальной оптимальности/невозможности.
- Своя площадка, явные резервные точки и известные площадки аппаратов того же типа участвуют в подборе. Явные посадочные места общей базы задаются в JSON, см. ниже. Географические точки не добавляются автоматически.
- Аппараты на земле и уже севшие участники остаются препятствиями. Для одной занятой точки очередь сама по себе не создаёт место. Перемещение с площадки и работа наземного персонала не моделируются.
- Перед первым запуском проверяются контрольные моменты взлётов и других фаз. Это **выборочная предпусковая проверка**, не сертификат возврата в любой момент при любых отказах. Текущий контроль в симуляции остаётся включённым.
- Событие сохраняет текущий расчётный заряд вместо служебных 100%. Название «Проверка безопасного возврата» отделяет конфликт траекторий от исчерпания батареи. При отказе: «Безопасный возврат не найден».
- Существующие межмиссионные запреты на пересечение исполнительных областей сохранены. Согласованное аварийное управление несколькими независимыми миссиями в общем воздушном пространстве не заявляется.

## Что прислать для диагностики

**Выполнение → карточка события → Диагностика ZIP**. Одного `*.incident.zip` достаточно для воспроизведения сохранённого события текущей версии. Внутри:

| Файл | Назначение |
|---|---|
| `data/report.html` | Краткое описание события, состояния БВС, причины и конфликты отклонённых вариантов |
| `data/input/mission.json` | Весь вход, участки, границы, базы, парк, батареи, погода, ограничения и источники |
| `data/plan/candidate.json` | Полный план, временные траектории, проверки и хеш входа |
| `data/incident/operation.json` | Неизменённый снимок запуска, стадия события, временные отметки и хеши |
| `data/incident/fleet-at-event.json` | Положение, высота, фаза и заряд каждого БВС на момент события |
| `data/incident/recovery.json` | Варианты возврата и свидетели конфликтов: пара БВС, время, обе координаты, высоты, дистанция и защитный порог |
| `data/incident/map.geojson` | Точки/линии конфликтов и маршруты возврата; это горизонтальная проекция |
| `data/incident/other-operations.json` | Контекст других сохранённых запусков |
| `data/incident/journal.json` | Модельные события и сохранённые контрольные записи, не полная история кликов |
| `data/checks/` | Повторные проверки плана и контрольных моментов возврата |
| `data/runtime.json` | Среда браузера; без cookies и токенов |
| `manifest-sha256.txt` | Контрольные суммы, не электронная подпись |

Скриншот/MP4 и одно предложение о последнем действии полезны, но не заменяют ZIP. Старый короткий `incident.json` содержит причины, но не исходные траектории — его недостаточно для точного геометрического воспроизведения.

```powershell
node --experimental-transform-types scripts/verify-mission-archive.ts "C:/path/run.incident.zip"
```

Проверка восстанавливает содержимое архива из снимка и повторяет поиск той же версии. `incident-diagnostic-reproduced` означает воспроизводимую диагностику, **не успешную посадку или реальный полёт**. Проверяются и заблокированные события. В архиве отдельно указаны исходная версия события и версия пересчёта.

## Общая база с несколькими местами

Необязательное поле `bases[].landingPads` сохраняется при JSON-импорте/экспорте. Места имеют отдельные координаты, совместимые типы и разрешение использования. Координаты должны быть выбраны оператором, а не придуманы алгоритмом. Пример структуры (координаты иллюстративные):

```json
{
  "id": "base-1",
  "name": "База 1",
  "coordinate": [30.3000, 60.0300],
  "landingPads": [
    {"id": "pad-1", "coordinate": [30.3000, 60.0300], "enabled": true, "kinds": ["multirotor"]},
    {"id": "pad-2", "coordinate": [30.3040, 60.0300], "enabled": true, "kinds": ["multirotor"]}
  ]
}
```

Приписка к базе определяется совпадением исходной точки посадки БВС с центром базы или одним из её мест. При наличии явных мест центр сам по себе не создаёт дополнительную площадку. Фактическая занятость проверяется по всем БВС, в том числе не назначенным на работу. Отдельный графический редактор посадочных мест в этом обновлении не добавлялся.

```powershell
npm run test:planner

```

Регрессии: три БВС/пересечения/низкий взлёт; очередь при фиксированной высоте; занятая точка; свободное/выключенное место общей базы; запасная площадка; недопустимый ветер; нехватка заряда; фиксированное крыло без зависания; воспроизводимость ZIP и обнаружение подмены.

### Проверенный срез 23.09.2026

- **590 тестов прошли** на Windows и при сборке Docker; проверка типов, линтер изменённых файлов и production-сборка успешны. У общего линтера остаются две прежние ошибки в несвязанных проверочных скриптах.
- **22 браузерные проверки прошли** на основном стенде 3016: групповой возврат четырёх БВС после усиления ветра; явный отказ при ветре выше предела с рабочей выгрузкой; полное выполнение Demo 2 с препятствиями и скачиванием отчёта, проверок, ZIP и MP4.
- Архив успешного возврата воспроизведён отдельной командой на Windows и Linux в Docker; архив заблокированного события — на Windows. В обоих по 18 файлов.
- Архив завершённой Demo 2 прошёл повторную модельную проверку: 53 проверки пройдены, 0 провалены, 9 внешних/физических проверок остаются `unknown` и не засчитываются за пройденные. MP4: H.264, 1280×720.
- Основной контейнер `healthy`, версия 0.3.6; 223 файла приложения, ядра и тестов совпадают с локальными исходниками. Машиночитаемые результаты и пути артефактов: [протокол проверки](release-0.3.6-verification.json).

Точный прежний запуск из короткого `run-1790182749482-ffzhy.incident.json` не воспроизводился: в нём нет полного входа и траекторий. Проверены соответствующая регрессия пересечения/низкого взлёта и новые реальные запуски браузерного тренажёра. Новая выгрузка ZIP устраняет этот недостаток диагностики.

После обновления нужны новые расчёт и подтверждение. Старые запуски не переодобряются и не переписываются автоматически. Данные пользователя не удаляются этой правкой. Поведение чистой демонстрационной сессии при перезагрузке страницы остаётся прежним.

Число тестов не является оценкой жюри. Физические полёты не проводились.
