# Стресс-проверка сохранённого плана

Дата: 20 сентября 2026. Политика: `fixed-route-retiming-v1`.

## Что можно заявлять

Перед запуском оператор может проверить, сохранится ли допустимость **того же маршрута и состава БВС** при усилении/повороте ветра, задержке вылетов и снижении исходного заряда. Проверка не заменяет расчёт новым более удобным маршрутом и не меняет выполняемую операцию.

Проверяется не только заряд: пересчитываются длительности фаз, занятость аппаратов между повторными вылетами, достижение срока, освещение, временные запреты, геометрия, непрерывное разнесение в полёте и занятость площадок на земле. Исходные маршруты предварительно проходят независимую от сохранённых флагов проверку экспортного пакета.

## Что происходит

1. Вход и полный выбранный кандидат связываются SHA-256, совместимыми с доказательным пакетом и подтверждением плана.
2. Проверяются схема, исходные маршруты, покрытие, метрики, журнал, обе проекции результата и сохранённые проверки.
3. Для каждого случая создаётся отдельная копия. Случаи не накапливаются; сочетание факторов задаётся отдельным случаем.
4. Геометрия, высота, назначения, последовательность работ и места посадки сохраняются.
5. При изменении ветра заново вычисляются скорости, длительности и линейный расход энергии. Последующий вылет того же БВС начинается не раньше исходного времени с задержкой и новой готовности после предыдущей посадки.
6. Заряд уменьшается один раз на указанное число процентных пунктов; остаток переносится между всеми вылетами. Будущей замены батареи нет.
7. Валидатор заново проверяет ограничения. Автоматического поиска обхода или нового безопасного разнесения нет: нарушение означает необходимость нового расчёта.

## Статусы

| Статус API | Что показывать оператору |
|---|---|
| `safe` | Случай пройден **в расчётной модели**; неизвестные факторы остаются неизвестными. |
| `unsafe_in_model` | Этот сохранённый план нарушает ограничения при изменении условий. Это не доказательство, что никакого другого плана не существует. |
| `not_checked` | Проверка не выполнена: неполный/неверный исходный план, неподдержанный профиль, превышение диапазона либо бюджета. Нельзя засчитывать как успех. |

Отчёт содержит остаток заряда, запас сверх требуемого резерва, время завершения, суммарный налёт и запас до срока. Если ресурс исчерпан или кинематика невозможна, метрики отсутствуют (`null`); вместо вымышленных чисел возвращается причина и пометка о непроверенных остальных ограничениях.

## Ветер и прогноз

Внутри одного случая ветер постоянный, а не случайный по каждой секунде. Снимок Open-Meteo не переписывается и не выдаётся за новый прогноз. Сохраняются исходные проверки облачности, видимости, осадков и области действия прогноза. При усилении ветра дополнительно проверяется исходный максимум порывов плюс заданная прибавка. Нового сетевого запроса в этом анализе нет.

## Ограничения — не скрывать на защите

- Только текущая батарея `installed-current-v1` и безопасность `continuous-occupancy-v1`.
- Пока только мультироторные фазы. Самолётный план получает `not_checked`, даже если основной решатель поддержит самолёты.
- Не более 60 вылетов, 1200 сегментов, 6 случаев, запрос до 2 МиБ, документ задания до 200 КиБ.
- Бюджет 100–5000 мс — мягкий, проверяется между проходами. Один синхронный проход может завершиться позже бюджета; это не система жёсткого реального времени.
- Модель расхода линейная и не калибрована логами; уменьшение заряда не моделирует физическое старение батареи.
- Не рассчитываются вероятность успеха, все возможные погодные реализации, новые маршруты или оптимальная стратегия реакции.
- `safe` не является сертификацией и разрешением реального полёта.

## API

`POST /api/planner/missions/analyze`, `Content-Type: application/json`.

```json
{
  "document": "полный объект MissionDocument v2, не строка",
  "candidate": "полный выбранный MissionCandidate, не строка",
  "perturbations": [
    {
      "id": "combined",
      "label": "Ветер +2 м/с, задержка и меньше заряда",
      "windSpeedDeltaMps": 2,
      "windDirectionDeltaDeg": 45,
      "startDelaySec": 300,
      "batteryReductionPct": 10
    }
  ],
  "maxComputeMs": 5000
}
```

Строки-заполнители в примере нужно заменить реальными объектами. Если `perturbations` отсутствует, выполняются четыре **раздельных** случая: +2 м/с, +45°, +300 секунд, −10 процентных пунктов заряда. Повторяющиеся ID, неизвестные поля, нечисловые и бесконечные значения отклоняются. Дубли ключей JSON запрещены. Чужой Origin — 403, тип не JSON — 415, параллельный анализ — 429, слишком большой запрос — 413, зависшая передача >5 секунд — 408.

## Воспроизведение проверок

```powershell
node --experimental-transform-types --test tests/mission-robustness.test.ts
```

Тесты проверяют неизменность источника, соответствие неизменённого случая исходным метрикам, перенос заряда через три вылета, превышение резерва, срок и 4D-запрет после задержки, пересчёт ветра/энергии, сохранение прогноза и рост порывов, подмену данных, неподдержанные профили, лимиты и защиту API. Это регрессионная проверка программной модели, а не полётные испытания.

## Повторная проверка скачанного отчёта

Кнопка экспорта в интерфейсе сохраняет самодостаточный JSON-пакет: `type: prime-mission-robustness-bundle`, `schemaVersion: 1.0`, исходный `document`, полный `candidate` и полученный `report`.

```powershell
node --experimental-transform-types scripts/verify-mission-robustness.ts bundle.json verification-new.json
node --experimental-transform-types --test tests/mission-robustness-verification.test.ts
```

Имя выходного файла должно быть новым. Проверяющая команда не перезаписывает вход, существующий отчёт, символическую ссылку или жёсткую ссылку на чужой файл. Максимальный пакет — 4 МиБ. Дубликаты ключей JSON, неизвестные поля доказательного отчёта, бесконечные числа и чрезмерная вложенность запрещены.

Протокол `default-four-case-replay-v1` проверяет **ровно четыре стандартных случая интерфейса**, их ID, порядок и параметры. Поэтому удаление «неудобного» случая или ослабление ветра не остаётся незамеченным. Произвольные комбинации, доступные в API анализа, этим форматом доказательства не поддержаны; нужен отдельный контракт набора испытаний.

Повтор использует приложенные исходные данные и пересчитывает маршруты, затем сопоставляет статусы, нарушения, неизвестные факторы, численные показатели и пояснения. Проверка не ограничивается совпадением хешей: подмена метрик вместе с пересчитанным злоумышленником хешем также отклоняется. Изменённые/пропущенные политики не заполняются значениями по умолчанию. Допуск сравнения чисел — 0,000001 в исходных единицах.

| Статус повторной проверки | Код завершения CLI | Значение |
|---|---|---|
| `passes-declared-model` | 0 | Все четыре первоначально проверенных случая воспроизведены. Отрицательный случай тоже может быть воспроизведён правильно; это **не означает**, что все случаи безопасны. |
| `incomplete` | 2 | Исходный отчёт или повтор оставил что-либо непроверенным, например из-за бюджета. Полное доказательство не заявляется; причины и неизвестные факторы сохранены. |
| `rejected` | 1 | Нарушена структура, привязка, полнота набора или результаты пересчёта. |

`allCasesSafeInModel` и `allDeclaredCasesRechecked` разделены. Времена создания и вычисления не выдаются за заново подтверждённые измерения. Повтор использует тот же расчётный модуль и геометрический валидатор — это независимость от **сохранённых результатов**, а не независимая реализация физики. Неизвестные свойства реальных БВС и внешней среды остаются неизвестными.
