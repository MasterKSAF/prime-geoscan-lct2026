# Прайм Planner 0.3.0 · шпаргалка демонстрации

[Версия для показа и печати](demo-guide.html) · [Запуск и устройство проекта](README.md)

Рабочий цикл: **задание → варианты → проверки → подтверждение → симуляция → экспорт**. Ядро 0.3.0, формат полной миссии 2.0. Галерея содержит девять синтетических сценариев. Это собственные проверочные примеры, не официальные эталоны Геоскана и не реальные разрешённые полётные задания.

## Подготовка

Открыть [локальный Docker-стенд](http://127.0.0.1:3016/planner). При необходимости запустить из корня проекта: `docker compose -f compose.planner.yaml up --build -d`. Для показа без внешних запросов тайлов отключить подложку. Подготовить свободный ID для копии, например `demo-session-27`.

Основной пример — «Автовыбор БВС: время, налёт и баланс». Не подменять живой расчёт заранее названными минутами. Если варианты совпали или поиск не нашёл полный план в бюджете, показать фактическое объяснение.

## Показ за 6 минут

| Время | Действие | Что объяснить |
| --- | --- | --- |
| 0:00–0:40 | «Сценарии» → «Автовыбор БВС: время, налёт и баланс» → предпросмотр → «Заменить текущее задание». Открыть «Паспорт миссии». | Есть конкретный вход: номер, описание, работы, окно, базы, АКБ и допущения. Три совместимых БВС отличаются скоростью, базой и доступностью батарей; назначения оставлены автоматическими. |
| 0:40–1:15 | «Сохранить как» → новый ID и имя → «Создать новую миссию». | Сохраняется отдельная запись со всеми параметрами. Исходная запись не перезаписывается; старое подтверждение плана не переносится. |
| 1:15–2:05 | «Редактировать миссию» из паспорта → «Ресурсы». Раскрыть параметры БВС и АКБ; показать группы назначений работ. Затем «Правила» и «Слои карты». | Можно задать Custom, ограничения аппарата, базу, совместимость и экземпляры АКБ. 4D-объём — контур, высоты и период действия. Для основного расчёта оставить подготовленные параметры. |
| 2:05–3:20 | «Рассчитать варианты» → «Сравнить и объяснить варианты». | Сравнить «Раньше закончить», «Меньше летать» и доступный «Баланс»: последнюю посадку, суммарный налёт, назначения, вылеты, замены АКБ и остаток. Баланс выбирается из найденных допустимых планов. |
| 3:20–4:10 | Прочитать проверки и допущения → подтвердить выбранный план → запустить симуляцию; пауза, скорость, ползунок до конца. | Карта, события, заряд и экспорт используют одни вылеты. Изменение задания или выбор другого варианта сбрасывает подтверждение. |
| 4:10–5:10 | Открыть сценарий «Ожидание временного запрета», рассчитать; затем «Отказ: ветер выше предела». | В первом примере старт ждёт открытия зоны. Во втором показать причину отказа и недоступное подтверждение. Отказ — содержательный результат проверки. |
| 5:10–6:00 | Вернуться к сохранённому основному заданию через «Библиотеку», пересчитать при необходимости. Показать JSON/YAML задания, индивидуальную выдачу и «Доказательства». | Задание можно загрузить обратно. План и пакет доказательств относятся к конкретному расчёту; их проверяет отдельная команда. |

Если времени меньше, пропустить расчёт временной зоны. Для семиминутного показа дополнительно раскрыть «Повторные вылеты и смена АКБ». Не пытаться продемонстрировать все девять сценариев за один проход.

## Возможности, которые удобно раскрыть по вопросу

- **Паспорт:** описание, окно, работы, ресурсы, условия и ограничения в одном месте; переход к редактированию и скачивание описания MD.
- **Редактор флота:** имя, воздушная скорость, допустимый ветер, ресурс, подъём, снижение, манёвр, координаты старта/посадки, совместимые работы, источник и допущения. Тип Custom задаётся явно; Геоскан 201 остаётся самолётом.
- **АКБ и назначения:** начальный заряд, готовность, зарядка, циклы, дата ввода и источник. Для каждой работы можно выбрать группу БВС; пустая группа означает автоматическое назначение среди доступных совместимых аппаратов.
- **Удаление БВС:** после подтверждения удаляются аппарат, его батареи и ссылки в назначениях. Должны остаться минимум один БВС и одна АКБ. Опустевшая ручная группа становится автоматической.
- **Обмен флотом:** JSON `prime-fleet`, версия 1.0; предпросмотр перед добавлением. Совпадение ID, нарушение лимитов или невозможность сохранить итоговую миссию отменяет импорт целиком. Существующие профили не заменяются.
- **Слои и 4D:** GeoJSON/KML для координат; JSON `prime-restrictions`, версия 1.0, для объёмов с высотами, временем и источником. Импорт объёмов также требует подтверждения и отклоняет коллизии ID.

Пределы интерфейса: до 8 работ, 10 БВС, 100 АКБ и 20 дополнительных объёмных ограничений. Файлы миссии, флота и объёмов — до 200 КиБ каждый. В галерее доступны полная миссия и отдельные примеры участков, объёмов и флота. Повторный импорт собственных профилей в ту же миссию отклоняется при совпадении ID; для опыта использовать отдельную копию с уникальными ID.

## Матрица девяти сценариев

Ожидания ниже описывают замысел входов, а не подменяют результат текущего прогона. Основной источник — [каталог в коде](../../lib/planner/mission-showcase.ts).

| № / ID | Сценарий | Что наблюдать |
| --- | --- | --- |
| 1 · `automatic-tradeoff` | Автовыбор БВС: время, налёт и баланс | Один RGB-участок, три разных профиля и пустые назначения. Сравнить фактический выбор БВС и три представления результата. |
| 2 · `mixed-fleet` | Три работы и смешанный флот | RGB, MS и IR; совместимость назначений, разные скорости, ИК-АКБ доступны позже. |
| 3 · `lidar-geophysics` | LiDAR и геофизический подвес | Отдельные правила плотности/шага, учебный подвес 10 м и проверка высот. |
| 4 · `repeat-sorties` | Повторные вылеты и смена АКБ | Один БВС с ресурсом 12 минут; несколько вылетов, батареи и обслуживание между стартами. |
| 5 · `timed-airspace` | Ожидание временного запрета | Запрет до 200 м на первые 15 минут; ожидание открытия без сокращения задания. |
| 6 · `height-obstacle` | Высотное препятствие под маршрутом | Препятствие 40 м и переход на заданной высоте 100 м; проверить вертикальный зазор. |
| 7 · `area-with-hole` | Участок с внутренним отверстием | Исходный Polygon с отверстием; сохранение геометрии и полноты назначенных полос. |
| 8 · `wind-limit` | Отказ: ветер выше предела | Ветер 20 м/с при пределе профиля 10 м/с; полный допустимый план не ожидается. |
| 9 · `insufficient-energy` | Отказ: недостаточный ресурс | Заряд 26% при резерве 25%; полного вылета не ожидается. |

## Как объяснить три варианта

«Раньше закончить» уменьшает время от начала окна до последней посадки, включая ожидания и обслуживание между вылетами. «Меньше летать» уменьшает сумму длительностей всех вылетов; параллельные полёты складываются.

«Баланс» — рекомендация с равными весами этих двух показателей, нормализованных по найденному допустимому набору. Это выбор существующего проверенного кандидата. Он может совпасть с основным вариантом; при отсутствии полного допустимого плана баланс не предлагается. Суммарный налёт характеризует использование ресурса, но не измеряет физический износ. Глобальная оптимальность не доказана.

## Что загружаем и что выгружаем

| Формат | Назначение | Обратная загрузка |
| --- | --- | --- |
| Полная миссия JSON / YAML, схема 2.0 | Работы, геометрия, окно, флот, АКБ, ограничения и допущения | Да, через «Импорт» и предпросмотр |
| Описание MD | Читаемый паспорт задания | Нет; это описание, не входной формат |
| GeoJSON / KML на входе | Участки, границы, запреты, точки баз; роль выбирается при импорте | Как координатный слой, не как полная миссия |
| Флот JSON `prime-fleet` 1.0 | Профили БВС и их АКБ | Через «Ресурсы» → «Импорт флота», с предпросмотром |
| Объёмы JSON `prime-restrictions` 1.0 | Геометрия, высоты, период и источник ограничений | Через «Слои карты» → «Загрузить объёмы JSON» |
| GeoJSON / KML плана, «План JSON» | Рассчитанные вылеты группы либо выбранного БВС | Не заменяет полный вход; совместимость с автопилотом не проверена |
| «Доказательства» JSON | Вход, результат, проверки, события, хеши и сведения о подтверждении | Для отдельного проверяющего инструмента |

GeoJSON/KML не загружает DEM. Картинка карты без координат не становится геоданными. Высотный объём препятствия не является цифровой моделью рельефа. KML плана прижат к земле; высоты передаются отдельными атрибутами, а не как достоверные абсолютные высоты.

## Доказательства и границы

[Отчёт версии 0.3.0](showcase-0.3.0.md) · [машиночитаемый свод](../../output/mission-showcase-0.3.0/summary.json). Пакеты проверки находятся в `output/mission-showcase-0.3.0/`. Число пройденных тестов и итоги следует брать из фактических файлов текущего прогона. Для скачанного пакета:

```powershell
npm run verify:evidence -- <путь-к-пакету.json> <путь-к-отчёту.json>
```

Ветер, облачность и видимость вводятся вручную и считаются постоянными. Прогнозы и фактическая телеметрия не подключены. Нижняя граница облаков использует общий локальный уровень высот миссии; автоматического перехода к реальным AGL/AMSL нет. Заданная высота проверяется, автоматический поиск лучшей высоты не выполняется.

Рельеф — неизвестный либо явно плоский; энергия — линейная модель; качество реальных снимков и измерений не подтверждается. Самолётные фазы 201 не валидированы. Нет службы разрешений, управления реальным БВС, моделирования отказов и гарантии поиска решения для любого входа. Статус «Выполним в модели» сохраняет эти границы, а неизвестные проверки остаются видимыми.

Библиотека хранится в браузере: другой порт — другое хранилище; очистка данных может удалить записи. Для переноса сохранять полную миссию JSON/YAML и отдельную резервную копию библиотеки.
