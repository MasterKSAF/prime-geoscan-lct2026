# Локальный HTTP-вход планировщика

Штатный production-запуск: `docker compose -f compose.planner.yaml up -d --build`.
Для уже собранного проекта без Docker: `npm start`; по умолчанию `127.0.0.1:3000`.
Параметры окружения: `PORT`, `PLANNER_HOST`, `PLANNER_WORKER_PORT` (внутренний порт, по умолчанию 3001).

## Причина изменения

При отклонении большого POST старый маршрут отменял чтение тела. В локальном Wrangler/Miniflare это воспроизводимо приводило к обрыву JSON-ошибки или HTTP 503 на следующем запросе. Повтор клиента скрывал проблему, но не исправлял её.

Теперь Node HTTP-вход принимает запрос полностью в пределах установленного лимита и лишь затем передаёт его расчётному серверу. Превышение размера, неверный тип/источник, занятый вычислитель, незавершённая или слишком медленная загрузка обрабатываются до Wrangler. Остаток отказной загрузки считывается без сохранения (не более 32 МиБ и пяти секунд), после чего отдаётся JSON-ошибка и закрывается соединение. Это устраняет также TCP reset при раннем закрытии через Docker. Уже истёкший timeout не получает дополнительного ожидания. Отмена клиентом не обрывает уже начатую передачу серверу. Повторов запросов нет.

## Ограничения сохранены

| Маршрут POST | Максимум тела |
|---|---:|
| `/api/planner/solve` — архивный API | 200 000 байт |
| `/api/planner/missions/solve` | 200 КиБ |
| `/api/planner/missions/solve-with-obstacles` | 12 МиБ |
| `/api/planner/missions/analyze`, `/contingency` | 2 МиБ |
| Последние два с `x-prime-obstacles: 1` | 14 МиБ |

Считаются фактические байты, в том числе для chunked-передачи без Content-Length. Приём тела ограничен пятью секундами; одновременные расчёты ограничены по группе маршрутов. Проверки схемы, размеров нормализованной миссии, допустимости и безопасности повторно выполняет ядро. Сжатые POST не принимаются. Базовый API нельзя расширить одним заголовком.

В Docker наружу на localhost опубликован только вход 3000→3016. Wrangler слушает 127.0.0.1:3001 **внутри контейнера**. Не обходить вход прямым запуском Wrangler: исходный дефект стороннего runtime не исправлялся в его исходниках. `npm run dev:planner` — отдельный режим разработки, не проверенный production HTTP-контур.

Нет публичной авторизации или гарантий защиты от любых сетевых атак. При заведомо бесконечной/превышающей защитный предел отказной передаче соединение принудительно закрывается; доставка JSON такому клиенту не гарантирована. Это не допускает пересылку тела вычислителю и не отменяет ограничений следующего запроса. Стенд по-прежнему только локальный; шлюз не управляет реальными БВС.

## Регрессия

```powershell
node --experimental-transform-types --test tests/planner-ingress.test.ts
node --experimental-transform-types scripts/verify-http-recovery.ts http://127.0.0.1:3016 output/http-recovery/final
node --experimental-transform-types scripts/verify-obstacle-http.ts http://127.0.0.1:3016 output/http-recovery/obstacles
```

Первый набор проверяет приём, отказ, границы байтов, обрыв, timeout и освобождение занятости с контролируемым upstream. Второй многократно чередует реальные отказные запросы и корректный расчёт без retry, включая chunked и медленную передачу. Третий повторяет первоначальную последовательность на полном KML экспертов, требуя целый JSON даже в ошибочном ответе.
