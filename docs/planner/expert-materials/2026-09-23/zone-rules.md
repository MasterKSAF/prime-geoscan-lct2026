# Ограничения высот и времени · ядро 0.3.9

В KML экспертов нет машинного расписания запретов. Поле `Altitudes` теперь разбирается автоматически: нижняя и верхняя границы имеют независимую систему отсчёта. Исходный текст сохраняется. Стенд не угадывает разрешения по цвету, названию или текстовым исключениям для других категорий воздушных судов.

В московском файле 341 зона: 335 диапазонов распознаны, шесть остаются консервативно закрытыми. Полный пообъектный аудит с хешами: [airspace-source-audit-2026-09-24.json](../../airspace-source-audit-2026-09-24.json).

## Как загрузить

1. Редактор → Данные миссии → Каталоги экспертов и образцы → Загрузить зоны KML.
2. В предпросмотре при необходимости загрузите **правила высот и времени (JSON)**.
3. Примените зоны и выполните новый расчёт.

JSON — массив объектов. `objectId` — стабильный порядковый ID (`item-1` и т. д.) внутри именно этого исходного KML. Смена порядка объектов означает другой исходник; его SHA-256 фиксируется в доказательствах.

```json
[
  {
    "objectId": "item-1",
    "altitudeReference": "AGL",
    "min": 0,
    "max": 149,
    "timePolicy": "interval",
    "startAt": "2026-09-24T12:00:00+03:00",
    "endAt": "2026-09-24T12:30:00+03:00",
    "basis": "simulation",
    "source": "Демонстрационный интервал для проверки алгоритма"
  }
]
```

Это **пример тестового ввода**, не полученное от экспертов разрешение. Для реальных данных указывайте `basis: operator` и проверенный источник.

| Поле | Смысл |
|---|---|
| altitudeReference | `AGL`, `AMSL`, `FL`, `mission-reference` или `unknown` |
| min, max | Нижняя/верхняя граница; `null` — не задана. Для FL сохраняются эшелоны, не метры. |
| timePolicy | `always` — постоянно; `interval` — заданный интервал; `unknown` — расписание неизвестно |
| startAt, endAt | ISO 8601 с часовым поясом. Для `always`/`unknown` оба `null`. |
| basis, source | Кто задал правило и на каком основании |

## Безопасное применение

- Без дополнительных правил используются распознанные высоты KML. Неизвестное расписание закрывает **указанный высотный слой** на всё окно миссии, а не все высоты от земли. Неразобранный диапазон сохраняет консервативное закрытие; неразрешённая верхняя граница не стирает известную нижнюю.
- AGL/AMSL переводятся относительно явно заданной плоской поверхности миссии; для AMSL вычитается её абсолютная отметка. Это не замена DEM. При неизвестном рельефе высоты не считаются достоверно приведёнными.
- FL переводится в барометрические метры множителем 30,48. По умолчанию используется **модель стандартной атмосферы ISA**, явно записанная в нормализации, подсказке и допущениях плана. Это не актуальное давление с метеостанции. Для иной привязки в миссии задаётся `airspaceAltitudeReference`; при `kind: unknown` пересчёт не выполняется.
- `mission-reference` означает общую локальную высоту модели.
- Временный запрет проверяется на протяжении сегментов, а не только при старте. При необходимости расчёт откладывает вылет.
- Все пересекающие район зоны берутся из полного каталога. Для ускорения геометрия локально обрезается рамкой района с запасом, без удаления отверстий и без упрощения контура.
- Невалидная геометрия поблизости, чрезмерная сложность или более 80 локальных частей зон останавливают расчёт. Неизвестная зона не становится пустым пространством.
- База проверяется у земли и с учётом окна миссии. Высокий слой над ней не запрещает само размещение; взлёт, набор высоты, маршрут, снижение и посадка проверяются отдельно. Препятствия около базы проверяются непосредственно по полному каталогу, без лимита 80 объектов для этой локальной проверки. Лимит построения маршрута не снят.
- Серый пунктир на карте означает слой вне высоты выбранной работы, а не отменённый запрет. Оранжевый слой затрагивает эту высоту. Никакой цвет не является разрешением на реальный вылет.

## Высотная привязка

Настройка интерфейса: «Каталоги экспертов и образцы → Высоты и время зон → Пересчёт эшелонов FL».

Необязательное поле миссии (старые входы не переписываются автоматически):

```json
"airspaceAltitudeReference": {
  "kind": "pressure-altitude-offset",
  "offsetM": 100,
  "uncertaintyM": 50,
  "source": "Явно заданная модель для проверки, не измерение"
}
```

Определение поправки: `барометрическая высота = AMSL + offsetM`. Для нижней границы: `FL × 30,48 − offsetM − отметка поверхности − uncertaintyM`; для верхней неопределённость прибавляется. Затем защитные запасы планировщика расширяют диапазон. В стандартной атмосфере поправка и неопределённость модели равны нулю; это идеализированная атмосфера, а не нулевая погрешность реального прибора. Другие варианты: `{ "kind": "standard-atmosphere", "source": "..." }` и `{ "kind": "unknown", "source": "..." }`.

Пример: UUR219 имеет FL100–FL980. При отметке модельной поверхности 150 м и ISA её нижняя граница равна 2898 м над модельной поверхностью, а не 0 м и не 100 м. UUR372 начинается от земли и не получает такого исключения.

## Время и особые условия

- `врем_ограничение`: без расписания — `unknown`, учитывается весь период миссии, подпись «постоянно» не используется.
- `пост_ограничение` и `запретная_зона`: отсутствие дат трактуется консервативно как постоянное ограничение по типу источника; актуальный внешний статус не устанавливается.
- Явный KML `TimeSpan` с двумя полными датами/часовыми поясами применяется. `TimeStamp`, неполная дата, отсутствующий конец или противоречивые даты не означают, что зона отключена.
- Исключения для государственной авиации, аэродромов, литерных рейсов и согласований сохраняются текстом. Автоматического права использовать их у миссии нет.
- Текст «Некорректная геометрия!» сохраняется как предупреждение; топология проверяется независимо. Исходные контуры не исправляются молча.

## Доказательства

ZIP содержит `data/sources/restrictions.kml`, `restrictions.provenance.json`, `data/restrictions/normalized.json` (версия производного формата 2.0) и `applied.json`. Сохраняются исходный текст, контрольная сумма, все ID, причины отказов, обе высотные основы, модель пересчёта, условия и интервалы. Проверяющий скрипт заново строит ограничения из источника и сравнивает результат: одного переписывания SHA-256 недостаточно для подделки слоя.
