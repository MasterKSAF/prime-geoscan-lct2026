# SourceCraft: полезное из презентации

Источник: [«Анализ кода в эпоху ИИ: это конец?»](originals/sourcecraft-ai-code-analysis.pdf), Андрей Кулешов, руководитель SourceCraft Security. [Публикация PDF](https://disk.yandex.ru/i/BRotk294jvzFKw). 59 страниц. Это вспомогательный доклад, не требования трека Геоскана.

## Содержание

- Стр. 15–24: статический анализ кода, анализ зависимостей и поиск секретов; необходимость разбирать ложные срабатывания.
- Стр. 25–29: важность контекста и бизнес-логики при проверке прав доступа.
- Стр. 30–34: обновление уязвимой зависимости само по себе не гарантирует прохождение проверок.
- Стр. 37–46: сочетание ИИ с воспроизводимыми инструментальными проверками; вывод модели не заменяет доказательство.
- Стр. 48–58: демонстрация разбора предупреждений, исправлений и аудита в SourceCraft. На экранах есть предупреждения о расходе AI-квоты; ничего не запускалось.

## Применение к PRIME - наши предложения

1. Перед сдачей проверять зависимости, утечки секретов, сборку и тесты, сохранять версии инструментов и отчёты.
2. Проверять KML/JSON как недоверенный вход: размеры, типы, числовые диапазоны, запрет внешних сущностей и сетевых ссылок.
3. Каждую найденную проблему подтверждать воспроизводимым тестом; не считать мнение ИИ доказательством безопасности маршрута.
4. Проверить выданный команде репозиторий SourceCraft и права экспертов, не заменяя существующий GitHub без отдельного решения.

Доклад не требует внедрять ИИ в управление БВС. Платные/квотируемые проверки не активировались, код никуда не передавался.
