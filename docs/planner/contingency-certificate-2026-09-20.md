# Предполётное подтверждение доступной посадки

Модуль: `lib/planner/mission-contingency.ts`, протокол `controlled-abort-interval-v1`.

## Что подтверждаем

Для **исправного БВС при исходном ветре, заряде и известных препятствиях** рассматриваем управляемое прекращение работы из любого момента каждого полётного сегмента. Например, отмену съёмки или отказ камеры, не затронувший полёт.

1. Мультироторный сегмент делится на непрерывные интервалы не длиннее 30 секунд по умолчанию.
2. При отмене внутри интервала выключается съёмка, но оставшееся движение до его конца сохраняется. При неизменной модели в опорной точке будут исходные координаты, время, высота и заряд.
3. Из этой точки строится отдельный путь на свою либо заданную запасную площадку. Проверяются ветер, ресурс до посадки с резервом, окно времени, препятствия, облака/видимость и воздушные коридоры.
4. Уход сравнивается со всеми другими БВС по их исходному будущему расписанию. Проверяются и занятые площадки до вылета/после посадки. Последующие вылеты прекращающего работу аппарата отменяются, поэтому он не исчезает с площадки.
5. Если короткий уход не найден, отдельно проверяется оставшийся **исходный коридор движения с выключенной съёмкой** до штатной посадки. Он не называется быстрым независимым аварийным возвратом.

Это не выборочная проверка нескольких кадров анимации. Для каждой опорной точки проверенный переход распространяется на весь предшествующий интервал именно по аргументу сохранения движения/времени/ресурса. Непросмотренные интервалы подтверждёнными не считаются.

## Два различимых результата

| Режим | Что означает |
|---|---|
| `independent-escape` | Рассчитан отдельный уход с текущей опорной точки. Не обязательно кратчайший среди всех математически возможных путей. |
| `planned-corridor-sensing-off` | Доступна посадка по оставшемуся исходному коридору, без получения новых данных. Это может занять почти оставшееся время исходного вылета. |

Числа обоих режимов выдаются раздельно: `independentAnchors` / `plannedCorridorAnchors`. Смешивать их в формулировку «везде найден мгновенный аварийный возврат» нельзя.

Для 201 сейчас подтверждается только второй режим. Самолётные дуги и фазы не разрезаются и не превращаются в зависание: точки решения располагаются на концах исходных сегментов. Поэтому фактическая задержка до точки решения может превышать 30 секунд; возвращается её реальный максимум. На контрольном профиле 201 она составила около 84,8 секунды. Это не характеристика реального автопилота и не норматив времени реакции.

## Где проходит граница доказательства

- Это **не** гарантия возврата при разрушении аппарата, потере управления, внезапном обнулении батареи, изменении ветра или появлении препятствия на оставшейся части текущего интервала. Для таких событий нужен новый расчёт либо отказ от автоматического возврата.
- Подтверждается управляемое прекращение работы одного БВС при продолжении остальных по исходному расписанию. Массовый одновременный отказ отдельно не доказан.
- Рельеф должен быть явно плоским. Неизвестный DEM не заменяется выдуманной безопасной поверхностью.
- Для отдельного ухода все известные ограничения консервативно закрываются на всю высоту/время. Это может отказать в реально допустимом обходе сверху или после открытия зоны; исходный проверенный коридор остаётся отдельным вариантом.
- `not_certified` означает **проверка не завершена или проверенный вариант не найден**. Это не доказанная математическая невозможность и не основание показывать зелёный статус.
- Модель ресурса, погоды и движения сохраняет все исходные допущения. Сертификат не удостоверяет физическое качество самолёта, реальное наличие запасной площадки, разрешение полётов или безопасность неизвестных внешних БВС.

## Интерфейс для интеграции

```typescript
await certifyMissionContingencies(document, candidate, {
  maxIntervalSec: 30,
  maxAnchors: 512,
  maxComputeMs: 3000,
});
```

Функция не изменяет задание/план. Сначала выполняется повторная проверка исходного кандидата. Результат связан с `inputHash` и `candidateHash`. В отчёте — интервалы, опорные точки, выбранные площадки, времена, остатки, полные сегменты пути, причины отказа, допущения и вычислительный лимит. Получение данных в режиме исходного коридора отключено семантикой `planned-corridor-sensing-off`: исходная фаза `survey` в геометрии может сохраниться, чтобы не подменить её скоростную модель.

Лимит времени ограничивает цикл опорных точек, а не обещает жёсткий предел всей длительности сетевого запроса: начальная повторная проверка и геометрические операции имеют собственную стоимость. Превышение числа опорных точек или бюджета делает общий результат `not_certified`.

Для первого показа предпочтительна проверка **по запросу**, а не незаметное изменение утверждённой миссии. Подтверждение/выполнение миссии и этот диагностический отчёт — разные действия.

## Воспроизводимые проверки

```powershell
node --experimental-transform-types --experimental-test-isolation=none --test tests/mission-contingency.test.ts
node --experimental-transform-types --experimental-test-isolation=none --test tests/mission-contingency-replay.test.ts
node --experimental-transform-types scripts/verify-mission-contingency.ts bundle.json NEW-verification.json
```

Восемь тестов: непрерывность всех интервалов; сохранение исходника/хешей; резерв; отказ при лимите; отклонение изменённого/неполного плана; неизвестный рельеф; настоящий отдельный облёт препятствия; честный резервный исходный коридор; движущиеся фазы 201 без ложного обещания 30-секундной реакции. Часть перечисленного проверяется в одном тесте.

Для офлайн-проверки комплект должен иметь вид `{ "type": "prime-mission-contingency", "schemaVersion": "1.0", "document": ..., "candidate": ..., "certificate": ... }`. В сертификате сохраняются `limits`. Проверяющий заново строит уходы из исходных данных и сопоставляет все интервалы, пути, остатки, выбранные режимы и ограничения. Сохранённые зелёные статусы не принимаются на веру; время CPU не сравнивается. Изменённый маршрут/заряд, скрытые интервалы и подмена типа ухода отвергаются. Неполный исходный отчёт не становится полным сертификатом даже если повторный расчёт успел закончиться.

Вход ограничен 16 МиБ. CLI создаёт только новый выходной файл; существующий файл и исходный комплект не перезаписываются. Возврат кода 0 означает подтверждённый модельный сертификат, 2 — неполный отчёт, 1 — ошибка или отклонение.

Локально 20.09.2026 прошли 8/8 тестов расчёта и 6/6 тестов повторной проверки, включая реальные файловые ограничения CLI и отказ при неизвестных полях кандидата даже с пересчитанным хешем. На профиле 201 отдельно подтверждены все 196 исходных фазовых интервалов, исключительно в режиме исходного коридора; независимый короткий уход там не заявлен. Это инженерная проверка конкретного релиза, не оценка жюри и не сертификат лётной годности.
