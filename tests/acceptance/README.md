# Приёмочные проверки трека №5

Это инженерные тесты готовности, **не официальная формула баллов жюри**. Они проверяют ожидаемое правильное поведение и сейчас выявляют дефекты. Падающие проверки не помечены `skip`/`todo` и не заменены проверкой наличия ошибки.

## Запуск

Из корня проекта при работающем локальном стенде на `127.0.0.1:3016`:

```powershell
node --experimental-transform-types --experimental-test-isolation=none --test tests/acceptance/track5-readiness.test.ts
```

Восемь тестов запускаются последовательно. A1–A7 используют локальные модули и синтетические данные; A7 — отдельный fake-indexeddb, не библиотеку пользователя. A8 делает один POST к реальному локальному API. Нет новых пакетов, внешних сетевых сервисов, настоящих БВС и зависимости от предыдущей папки `output`.

Для A5 используется отдельно вычисленная точка сближения, без вызова производственной функции проверки разделения. Найденная точка доказывает нарушение; отсутствие найденной точки не является непрерывным доказательством безопасности любого маршрута.

Без `--experimental-test-isolation=none` текущая Windows sandbox запрещает дочерний процесс Node (`spawn EPERM`). Флаг сохраняет реальные тесты, меняет только режим их запуска. Ошибка запуска не учитывается как ошибка продукта.

Этот набор расположен отдельно от существующего `tests/*.test.ts`: `npm run test:planner` не включает вложенную папку. Для приёмки необходимо явно выполнить **оба** набора. Производственные модули и package.json в рамках этой проверки не менялись.
